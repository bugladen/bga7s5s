# Rumors of the Crimson Roger (_02036)

## Implemented

- Scheme resolve: one `createRenownAddedToLocationEvent` with **amount 2** to `Game::LOCATION_CITY_DOCKS` (single notify with `${amount}`).
- **Action_02036a:** `SchemeCityAction`, Pirate performer, opposing non-Pirate at same location → state `02036` (pick target) → `createTransitionEvent` to target controller + `targetChosen` → EVENTS → `02036_2`. Opponent **Pass** = move target Home (`createCardMovingEvent` initiating player = scheme owner, same pattern as Action_02025). Opponent **discard from hand** = `createCardDiscardedFromHandEvent` with `sourceId` = scheme card id, **no move**.
- **Action_02036b:** Adjacent-to-Docks check via `in_array(LOCATION_CITY_DOCKS, getAdjacentCityLocations($loc, false))`, not already on Docks; resolves entirely in `EventActionTriggered` like Action_01046b (no substates).

## WHY

- **Discard prevents move:** Standard reading of “Move … unless their controller discards” — paying the discard cancels the forced move.
- **`announceAction` only when pirate picks target:** Matches Action_02034 (Torvo). If we called `announceAction` while the active player was the opponent, the log would show the wrong `player_name` for “used the Action”; `ActionActivated` should tie to the scheme owner’s turn when the choice is committed.
- **Action B no substate:** No discretionary targets after performer selection; immediate move + `createActionResolvedEvent` keeps parity with Action_01046b-style abilities.
- **Zombie on `02036_2`:** `actFromCardPass` so zombies do not auto-discard from hand (worse for the zombie).
