# _03070 double carriage returns

## Context
Last work: Comforting `_03070` via create-risk + skill fold (C.6 excess / CHALLENGE_STAT). Eddie flagged `_03070.php` has double CRs.

## What was wrong
File bytes were `0D 0D 0A` (`\r\r\n`) on every line — not intentional blank lines, doubled CR before LF. Hex confirmed at start: `<?php\r\r\n\r\r\nnamespace...`. Neighbors (`_03069`, `Maneuver_03070`) are normal CRLF (`0D 0A`).

## Fix
Replaced `\r\r\n` → `\r\n` in place. Size 1464→1417, lines 94→47, CRCRLF=0. Content unchanged. WHY normalize to CRLF (not LF): match sibling faf PHP files; user rule is leave endings intact unless asked — here the ask *was* the double-CR bug.
