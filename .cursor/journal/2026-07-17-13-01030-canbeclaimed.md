# Action_01030 CanBeClaimed Availability Gate

Eddie: Action_01030 needs to check `theah->canLocationBeClaimedBy` to be used.

## Context

Continuation of today's claim-gate sweep (01095a, 01130, 02029, 01075, 01080, 01028, …).
Resolve path already guarded claim emit with `canLocationBeClaimedBy` (EventLocationPressureResult).
Availability / performer list did not — Pull the Strand could still be played from hand when every
viable Strega was at a Leshiye / Indomitable Will location.

Unlike 01075 (fixed performer location), 01030 picks among Sorcerer+Strega performers at different
city locations. So claimability is per-performer, not a single location check.

## Changes

Extracted `getEligiblePerformers()` (Action_01103a pattern) used by both `isAvailableToPlayer` and
`getPerformersForAction`. Existing filters (city with opposing chars, unengaged, can pressure
Influence, Sorcerer+Strega) plus:

```php
$theah->canLocationBeClaimedBy($playerId, $character->Location)
```

WHY shared helper: availability and pick list must stay identical — otherwise Risk shows as
available but performer chooser is empty (or vice versa).
WHY gate at availability (not only resolve): pressure-then-claim is the point; spending the hand
Risk when every candidate site is unclaimable wastes the card.
WHY filter performers not "any claimable city location": performer location IS the pressure target;
a claimable site with no eligible Strega there is irrelevant.
WHY `canLocationBeClaimedBy` not `$location->CanBeClaimed`: central API, `$playerId` reserved for
future per-player rules. Resolve-time recheck kept (claimability can change mid-flow).

No JS changes — performer selection already consumes `getPerformersForAction`.
