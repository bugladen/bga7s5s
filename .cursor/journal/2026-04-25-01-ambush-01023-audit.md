# Ambush _01023 Audit

## Card Text
- **Passive:** While you have a character with Brute at the location of a challenge, this card has -1 cost.
- **Reaction:** When a challenge is issued - Other characters cannot intervene.

## Bug Found: Wrong function call in getReactionFromHandDiscount

Line 141 called `getCharactersAtLocation($challengeLocation, $owner->ControllerId)` — but `getCharactersAtLocation` signature is `(string $location, bool $includeUncontrolled = false)`. The second parameter is a bool, not a player ID. Passing a non-zero int gets cast to `true`, meaning it returned ALL characters at the location (including uncontrolled) regardless of faction.

Line 143 then filtered by `$character->OwnerId == $owner->ControllerId` — using `OwnerId` instead of `ControllerId`. These differ when character control changes hands. "You have a character" means characters you CONTROL, not characters you originally owned.

### WHY this matters
1. **Type mismatch**: `getCharactersAtLocation` with truthy second param returns uncontrolled characters too. An uncontrolled Brute at the challenge location whose OwnerId matched the player would incorrectly grant the discount.
2. **OwnerId vs ControllerId**: If player A takes control of player B's Brute, player A should get the discount (they control it). With `OwnerId`, player B would get it instead. The entire codebase consistently uses `ControllerId` for "you have/control" checks (Reaction_01014, 01016, 01065, 01137 all use ControllerId).

### Fix Applied
Replaced `getCharactersAtLocation($challengeLocation, $owner->ControllerId)` with `getCharactersAtLocationByPlayerId($challengeLocation, $owner->ControllerId)` — the correct function that filters by ControllerId. Removed the redundant OwnerId filter since the function already handles player filtering.

### Reaction Logic: CORRECT
The intervention blocking is correct:
- Accept/Intervene are mutually exclusive actions in the same `activeplayer` state (`HIGH_DRAMA_CHALLENGE_ACTION_ACCEPT_CHALLENGE`)
- `PreventIntervention` flag set during reaction processing, checked in `eventCheck` for `EventCharacterIntervened`
- Flag properly resets on `EventChallengeAccepted`, `EventChallengeRejected`, `EventPlayerTurnEnd`, and `EventDuelStarted`
- The `EventChallengeAccepted` reset doesn't cause issues since accept and intervene can't both happen
- Alternative intervention paths (e.g., Mourad/Reaction_02003) also go through `eventCheck`, so they're also blocked

### Cost Reduction: CORRECT (after fix)
- Discount is in `getReactionFromHandDiscount` — the right place since this is a Risk card whose only playable ability is the Reaction
- Confirmed by comparing with Reaction_02058 (same pattern) and maneuver-based discounts (use `getManeuverFromCombatCardDiscount` instead)
