## WHYs pinned
- **02041**: Scoundrel actor only. Resolve sets `CHALLENGE_STAT` to Finesse. Notify `challengeStat` is the raw CSS key; `duelStat` is the translated label. `isAvailable` does not null-check the duel actor — don't pass null.
- **02042**: +1 gamble reveal only for her controller, in the city, same location. Reaction offers when a revealed card has Sorcery and a friendly Sorcerer is at the actor's location (Ivy herself counts). Pass clears the id list and does not set Used. Unknown `takeSorcery-` id ends the reaction but leaves the list. Take decrements `GAMBLE_REVEAL_COUNT` and sets Used.
- **02043**: Implements `IHasManeuvers` with zero printed maneuvers so a copied maneuver can be `addManeuver`'d. Dashed Influence (cannot pressure Influence — matters for 02045).
- **Technique_02043a**: `ResetOnDayEnd` true, `ResetOnDuelEnd` false (Used survives DuelEnd, clears at dusk). Arms only when the twins are the duel actor who resolved a maneuver. Resolve clones onto the twins with a new id (`{twinsId}_Maneuver_…`), queues Activated then Resolve then Calculate. Does NOT re-fire the original. Locker send waits for EndOfRound (or DuelEnd if still pending). **NewRound clears `pendingLockerSend` without sending.** Cancel drops the pending send and the clone but does not clear `maneuverPerformed`. `lockerCombatCardId` is a string property; card ids land there as strings. First friendly combat card in the round list is the one marked, even if it has no matching maneuver. Opponent combat cards are skipped.
- **Technique_02043b**: In-duel + Flourish in *your* discard (`clienttranslate('Flourish')`). Resolve transition `02043b`. Confirm removes from discard and `createCardAddedToFactionDeckEvent(..., onTop=true)`.
- **02044**: Challenge block is Forums uncontrolled (`eventCheck` throws `\BgaUserException`), independent of where she stands. Influence pressure while she is at the Forums and the location is adjacent (Docks, Bazaar — not the Forums, not Home, not Ole's Inn) ORs `SOLOMONIA_PRESSURE_TYPE` via `setGlobalFlag` and stores `SOLOMONIA_ID`. Uncontrolled Solomonia or Combat pressure does nothing.
- **02045 resolve**: Outermost locations come from `getPlayerCount()` (the property, not the global). 2 players: Docks + Bazaar. 3: Ole's Inn + Bazaar. Second step: exactly two distinct locations, neither the chosen one. Then renown +1 each and `EventSchemeMovedToCity`.
- **Action_02045**: Full override of `isAvailableToPlayer`. SchemeAction's Player Home check is intentionally skipped — available from hand or city once `ChosenLocation` is set, if a Sorcerer who `canPressure(Influence)` is there. Dashed Influence (Miyato) does not qualify. Trigger: sorcerer start + Influence pressure + transition `pressureLocation`. Played/ActionResolved wait until search finishes (success opens `02045`; failure fires them immediately). Pass throws `\BgaUserException` (not Framework UserException) while a Dar Matushki or Poluchatel remains in the faction deck. Empty pass still shuffles and finishes the sorcery. `CHOSEN_PERFORMER` must be set before played events or the int param type-errors.
- **02046**: First chooser does not validate that the location is a city location. Second must differ; pass is `nextState("")`. Recruit always engages (no phase check). Muster engages only when `getCurrentMainStateId()` prefix is 30–69. 402047 and 300000 engage; 2602046 and 700000 do not.
- **02047**: Equip adds trait `"Sorcerer"` (not clienttranslate). Unequip removes it.
- **Action_02047**: Availability is `getAvailableAttachmentsAtLocation` (unattached only). The click ALSO rejects `isControlled()`. A controlled unattached attachment makes the action look available, then throws. Artifact adds Renown at the host's location; otherwise locker only. ActionResolved uses the host's controller.
- **02048**: In hand. Holds the first effect from an opponent `Risk` that `implements IRiskThatTargetsCharacters` (02049 does; 02041 does not) targeting your city character: CharacterTargeted, Engaged, Moved, Wounded, ChallengeIssued (defender), AttachmentEquipping. Cancels it, deletes its batch, offers pressure/decline. Decline re-emits and `skipNextEvent` swallows the next matching event so the re-emit does not re-offer. Pressure pays in-hand reaction, then `EventRiskReactionTriggered` calls `pressureLocation` with a null performer at the saved location, Combat, `NORMAL_PRESSURE_TYPE`. Success does not re-emit; later effects from `RiskSourceId` auto-cancel (equip also discards the attachment). Failure re-emits. Turn end clears the latch and any still-held event, so a late failure result cannot put the effect back. Used still blocks a fresh offer after the latch clears.
- **02049 action**: `JUSTICE_SERVED_COLD_CHALLENGE_TYPE` is 16. Trigger sets Combat + that type and does NOT ActionResolved (challenge resolution does). `canChallenge` is "controlled", so engaged still opens the action. `isValidTarget` does not require the target to be controlled — an uncontrolled Thug is a legal click. Availability scan uses opposing characters, which skips uncontrolled.
- **Maneuver_02049**: Trait gate is availability only. Calc adds +1 Riposte whenever the maneuver id matches, with no second trait check. `IN_DUEL` false returns before touching a null adversary.
- **02050**: Printed trait is `Beauracracy` (misspelled). Do not "fix" the test to Bureaucracy. Offer when in hand and some city character at a *different* location `canPressure(Influence)`. Home characters are not in `getCharactersInCityByPlayerId`. Decline clears `TriggeredLocation`. Paid reaction **assigns** `USSURAN_INTRIGUE_PRESSURE_TYPE` (replaces any existing PRESSURE_TYPE bits; does not OR). Renown move happens on `EventLocationPressureResult` success, not inside `pressureLocation`. The added renown is `isMove=true`, but the re-offer guard is `Used`, not `isMove`. Same batch id on moving/remove/add.
