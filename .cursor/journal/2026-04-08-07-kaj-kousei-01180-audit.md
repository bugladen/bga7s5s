# Kaj Kousei (01180) Audit

## Card Text
> Negotiable (You may parley when paying for this card.)
> While equipping an Artifact to one of your characters, it has -1 cost.
> **City Action:** Reveal the top four cards of the City Deck. You may equip a revealed Artifact to your character at this location. Sink the rest.

## Bug 1: Affordability check subtracted discount from wrong side

In `actFromActionWithId` state 01180_4, the pre-check was:
```php
if ($cost > $wealth - $discount)
```
This subtracts the discount from the player's available wealth instead of from the card's cost. Effect: players get rejected even when they can afford the equip. Example: 3-cost Artifact, 1 discount, 3 wealth → effective cost is 2, player has 3 wealth, should be fine. But code does `3 > 3-1` → `3 > 2` → error.

Every other equip action in the codebase follows `$cost = WealthCost - $discount; if ($handWealth < $cost)`. Fixed to match that pattern, including the `if ($cost < 0) $cost = 0` guard.

### WHY this was wrong
The developer was thinking about it from the wrong direction — "does the player have enough after accounting for discount" — but applied the discount to wealth instead of cost. The math is equivalent only when you flip the sign correctly, and this particular formulation got it backwards.

## Bug 2: Artifact validation used && instead of ||

```php
if (! $chosenCard instanceof Attachment && ! $chosenCard->hasTrait('Artifact'))
```
With `&&`, error only fires if BOTH conditions fail. A non-Artifact Attachment (like a regular Item) would pass validation. Fixed to `||` so the card must be BOTH an Attachment AND have the Artifact trait.

## Bug 3 (minor): Missing cost floor in payment state

In `actFromActionWithIds` state 01180_5, `$cost -= $discount` had no `if ($cost < 0) $cost = 0` guard. Every other payment flow in the codebase has this. Added for consistency.
