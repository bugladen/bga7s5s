# A Fine Addition (_04029)

## Context
User asked to finish `_04029` using Create Risk skill and Robbery (`_01113`) as the take-control-and-equip pattern guide. Card is Montaigne bas Risk with En Garde Merchant Action only.

## Pattern choice
- **Pattern B** `RiskAction` (not City Action — heading has no "City").
- En Garde = `!$performer->Engaged` precondition; Merchant = `hasTrait("Merchant")` performer gate.
- **Target attachment** → `IAbilityThatTargetsCards` on Action (like Robbery), not `IRiskThatTargetsCharacters`.
- Steal flow cloned from `Maneuver_01113` equipped path + `Action_01113` pay state: unequip → discard from play → controller swap → hand → `PAY_STATE_EQUIP_ATTACHMENT` → wealth pay → equip.
- Draw rider: last controller (`CHOSEN_OPPONENT` global stashed at steal) draws unless **your** Leader has Villain trait (`getLeaderByPlayerId` null → still draw).

## WHY not Robbery City Action shape
Robbery Action steals from **discard pile** with opponent chooser first. _04029 text is **equipped on opposing character at location** — one chooser listing attachments on `getOpposingCharactersAtLocation` (host name in button label for disambiguation).

- States `404029` / `4040292`; transitions `"04029"` and `"04029_2"` in `states.inc.php`.
- JS mirrors `04019` (attachment buttons) + `01113_3` (wealth pay) in bas trio + `EventHandlers` payForCard.

## Bugfix: Kaspar's Panzerhand (_01047) stealable via unequip→equip
**Report:** _01047 ("cannot be moved") was a legal target for Action_04029.

**Root cause:** _01047 only blocks `EventAttachmentMoved` in `eventCheck`. Steal flows (04029, Robbery 01113) use unequip → discard → hand → equip — they never emit `EventAttachmentMoved`, so the gate never ran.

**Fix:** `Attachment::canBeMoved()` default true; `_01047` overrides false. Filter in `getStealableAttachments` (04029) and equipped path in `Maneuver_01113`. WHY mirror `canBeDiscardedFromCity` pattern (journal 2026-07-24) — chooser/availability predicate, keep `eventCheck` for direct `EventAttachmentMoved` emitters like Kalla 01197. **Not** applied to `attachmentsAvailableFromOpponentDiscardPile` — "cannot be moved" only applies while equipped.
