# Stubborn (_01140) Audit

## Card Text
> Reaction: Before your character moves • Cancel their movement. (Even during Dusk.)

## Reaction Analysis

Reaction_01140 extends CardReaction and implements ICancelReaction. Triggers on `EventCardMoving`:

### Trigger Conditions (handleEvent)
- `EventCardMoving && !event.canceled && isAvailable() && !event.unstoppable`
- Owner card must be in `LOCATION_HAND`
- Skips if this card already declined via `cancelDeclinedByCardIds`
- Moving card must be `Character` controlled by same player as owner

### "Before your character moves"
`EventCardMoving` fires before the actual move. The EventHub converts it to `EventCardMoved` (which does the actual move) only AFTER card handlers run, and only if `!$event->canceled`. So the reaction intercepts at the right timing. ✅

### "Cancel their movement"
Sets `$event->canceled = true` immediately in `handleEvent`. The EventHub checks `if ($event->canceled) return;` before processing any event, so the move never happens. ✅

### "Your character"
Checks `$card instanceof Character && $card->ControllerId == $owner->ControllerId`. Doesn't check `initiatingPlayerId`, meaning it works regardless of who initiates the movement (your own ability or opponent's ability). This is correct — card says "your character moves" not "you move your character." ✅

### "(Even during Dusk.)"
Dusk movements in `stDuskPhaseCleanup` create standard `EventCardMoving` events via `EventFactory::createCardMovingEvent()` — these have `unstoppable = false` by default. The only place `unstoppable = true` is set is Reaction_01144. Dusk events are processed through `DUSK_PHASE_CLEANUP_EVENTS` → `stRunEvents()`, which runs card handlers normally. The state machine has proper reaction states for Dusk cleanup (`DUSK_PHASE_CLEANUP_REACTIONS` and `DUSK_PHASE_CLEANUP_PAY_FOR_REACTION`). No mechanism exists in the codebase to block reactions during Dusk, so the parenthetical is a rules reminder for players, not something requiring special code. ✅

### Cancel/Decline Flow
- **Cancel**: Stacks `ReactionPayTransitionEvent` and `EnteringPayStateEvent`, marks `setUsed(true)`. After payment, card is discarded from hand and `EventRiskReactionTriggered` fires (just sends notification message). Movement stays canceled.
- **Decline**: Re-queues the cloned event (which has `canceled = false` since clone was made before canceling original). Adds owner ID to `cancelDeclinedByCardIds` to prevent re-triggering. Reaction stays available for other movements.

The clone-before-cancel pattern is correct: `$this->eventCardMoving = clone $event` happens before `$event->canceled = true`, so the clone preserves the uncanceled state for re-queuing on decline.

### Payment
WealthCost = 0, so payment always succeeds trivially.

## Minor Observations (not bugs)
- Redundant `$owner = $this->getOwningCard($event->theah)` call at line 57 — identical to line 48, same variable, no mutation between. Harmless.
- `setUsed(true)` in `performReaction('cancel')` is technically redundant since the card gets discarded from hand after payment (so `LOCATION_HAND` check prevents re-trigger). But it's a safety net and consistent with the reaction's once-per-use semantics.

## Verdict
No issues found. Implementation correctly captures the card text functionality.
