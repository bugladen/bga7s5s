# Otto Streit (01038) Audit

## Card Text
**City Action:** Reveal the top three cards of your deck. Put a revealed attachment into your hand. Sink the rest.

## City Action gating
`isAvailableToPlayer` checks parent (owned, not used) + `$theah->cardInCity($otto)`. Correct.

## Reveal top three cards
`handleEvent` calls `getCardsOnTopOfPlayerFactionDeck($otto->ControllerId, 3)`. This function handles the edge case where the deck has fewer than 3 cards (shuffles discard pile into deck). Notification announces all revealed card names and attachment count to all players. Correct.

## Put a revealed attachment into your hand
State 01038_3 lets the player select one attachment. JS enforces:
- Single selection mode (1) only when attachments exist
- Non-attachments get `_7sfs-unselectable` CSS class
- Click handler in EventHandlers.js rejects non-attachment selections and manages confirm button enable/disable

PHP validates:
- Card is among the top 3
- Card is an `instanceof Attachment`
- Uses `createCardRemovedFromPlayerFactionDeckEvent` (signal event, no EventHub handler — physical removal is handled by `moveCard` in the `EventCardAddedToHand` handler) + `createCardAddedToHandEvent`

## Sink the rest
Non-chosen cards get `createCardAddedToFactionDeckEvent(false)` → `insertCardOnExtremePosition(cardId, deckName, false)` → bottom of deck. Standard sink pattern. Correct.

## State flow
01038 (multipleactiveplayer: all acknowledge reveal) → 01038_2 (game: set current player) → 01038_3 (activeplayer: choose attachment or pass) → HIGH_DRAMA_PLAYER_TURN_EVENTS. Clean flow.

## Bug found and fixed: mandatory attachment selection

The card text says "Put" not "may put" — this is mandatory. Compare to Kaspar's "may recruit it" which explicitly uses "may" for optional actions. When attachments are present among the revealed cards, the player MUST choose one.

**Before fix:** Pass button was always available in state 01038_3, even when attachments were found. This let the player skip taking an attachment and sink everything.

**Fix applied:**
1. PHP `actFromActionPass`: Added validation loop — if any revealed card is an Attachment, throws `BgaUserException`. Also updated the notification message from "chooses not to put any Attachments" (implying choice) to "reveals no Attachments among the top cards" (stating fact).
2. JS `OnUpdateActionButtons.7s5s.js`: Pass button only shown when `args.args.cards.some(card => card.type === 'Attachment')` is false.

WHY both sides: JS hides the button for good UX, PHP validates server-side to prevent exploits or race conditions.

## EventCardRemovedFromPlayerFactionDeck — not a bug
This event has no handler in EventHub.php. It's used purely as a signal event for `eventCheck` (card-level reactions). The physical card movement is handled by `EventCardAddedToHand`'s `moveCard` call. Same pattern used in `_01016.php`. This is intentional.
