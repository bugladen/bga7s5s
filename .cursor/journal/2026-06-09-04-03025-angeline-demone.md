# Angeline Dèmone (03025) — Reaction Implementation

## Card Details
- **Leader**, Montaigne faction
- **Stats:** Resolve 9, Combat 3, Finesse 3, Influence 1, CrewCap 5, Panache 6
- **Traits:** Leader, Villain, Duelist, Pirate, Sorcerer, Montaigne
- **Text:** 
  1. "After Angeline moves to a **City** location, wound an engaged character opposing her."
  2. "Technique: +1 [Riposte]"
  3. "Gambling Technique: Move both participants to any **City** location. (The duel continues)"

## Implementation: Reaction_03025.php

### Pattern Applied
Pattern D — Button-based Reaction. The reaction is triggered by Angeline's move, not a player choice, so the trigger (`EventCardMoved`) comes from the game engine. The effect (wound an engaged opposing character) requires player choice, so buttons are presented.

### Design Decisions

#### WHY `EventCardMoved` on Angeline's own move (not enemy)
- The printed text says "**After Angeline** moves" — it's about Angeline's action, not someone else's.
- Filter: `$event->cardId == $owner->Id` (the card moving is Angeline herself).
- Similar to Ise's "After enemy moves to my location," but inverted: we care about the Owner's move, not the opponent's.

#### WHY check `locationInCity($event->toLocation)` before triggering
- The text restricts the trigger to City locations: "moves to a **City** location."
- `Theah::locationInCity($location)` returns true for the 5 city locations (Oles Inn, Bordello, Cathedral, Docks, Market).
- Gate in `handleEvent` so non-city moves don't offer a reaction.

#### WHY check for eligible targets BEFORE queueing the transition
- If no engaged opposing characters exist at Angeline's new location, there's no valid effect target.
- Queuing the transition anyway would leave the player with a useless reaction prompt (only "Pass" button available).
- The valid-target precondition is enforced: `if (count($this->getEligibleTargets(...)) > 0)` in `handleEvent`.

#### WHY `$owner->Location` is already updated in `handleEvent`
- `EventCardMoved` is a post-tense event (card has already moved).
- EventHub's handler (EventHub.php:650) updates `$card->Location = $event->toLocation` BEFORE firing card reactions.
- So by the time `CardReaction::handleEvent` runs, `$owner->Location` is already the new location.
- `getEligibleTargets` filters correctly without needing a temporary update.

#### WHY filter opposing characters by `Engaged == true`
- The effect text says "wound an **engaged** character opposing her."
- `getEligibleTargets` ORs two filters: `getOpposingCharactersAtLocation` (controller ≠ Angeline's) AND `$c->Engaged`.
- The "Engaged" gate ensures only characters with the Engaged flag set are selectable.

#### WHY wound cost is 1
- The effect text says "wound an engaged character" without a number.
- Default wound cost is 1 per instance of the effect. The Reaction_03025 doesn't specify a different cost, so it's 1 wound.
- `createCharacterBeingWoundedEvent($character->Id, $owner->Id, 1, ...)` — 1 wound per button click.

#### WHY no state class
- This is a button-based Reaction — the player chooses which character to wound (or Pass).
- No multi-step flow needed (unlike an Action that might need a picker state and a finalization state).
- The framework's `performReaction` loop handles the button dispatch; no custom GameState required.

### Reaction Wiring
- **Class:** `Reaction_03025 extends CardReaction`
- **Trigger:** `EventCardMoved` with `cardId == owner->Id` AND move destination is a city location
- **Valid-target precondition:** At least one engaged opposing character at Angeline's new location
- **Effect buttons:** One button per eligible target (`"wound-{characterId}"`)
- **Pass button:** Always present
- **Effect:** Queue `createCharacterBeingWoundedEvent` for the chosen character, set `Used = true`
- **No state class:** Returns via `$game->gamestate->nextState("done")` directly to the dispatcher
