# I Know That Trick vs Sabre (04054)

## Report
User: Trick unable to copy either technique on enemy's equipped Sabre `_04054`
(+1 Thrust / Engage • +1 Riposte).

## Root cause
`Maneuver_01165` listed candidates via `getTechniquesAvailableToPlayer` →
`isAvailableToPlayer`. `Technique_04054b` (and siblings 04026/04055a) gate on
`getDuelRoundActor()->Id === getOwningCharacter()->Id`. While Trick's player is
the actor, the sabre's owner is the adversary → Engage technique filtered out.

Same class of bug Dame already fixed (2026-09-07 Kaspar/Eisenfaust): copy effects
must not re-check source play prerequisites.

+1 Thrust (`Technique_PlusOneThrust`) has no actor gate — should still have listed.
User said "either"; Engage was definitely dead; aligning the picker to Dame shape
anyway so any future gated attachment techniques copy.

## Fix
- `Maneuver_01165`: `getCopyableTechniques()` walks adversary + attachments with
  `getTechniques()`, skips only `IsTemporaryCopy`. No `isAvailableToPlayer`.
- Copy path: set `IsTemporaryCopy`, unique `Id` (`actorId_copy_ClassId`), clear Used
  — Dame/Yepikhodov shape. Keep `copiedTechniques` for ManeuverCanceled cleanup.
- Args: `getPropertyArray` (lowercase id/name). JS updated to match; Pass button
  moved outside forEach.
- Engage-as-cost on `Technique_04054b` / `04026` / `04055a`: skip when
  `IsTemporaryCopy` or `IsEffectsOnlyCopy` (same WHY as 01049 / 04017). Otherwise
  a Character-hosted copy would try to engage the participant.

## Tests
`tests/regression/Maneuver_01165_Test.php` — availability+picker lists both sabre
techniques; Engage resolve skips CardEngaged when IsTemporaryCopy.

## Do not regress
- Playing Sabre Engage as the owner still engages the attachment.
- Blanked-character Fate's Silence still only matters for *playing* techniques,
  not for Trick's copy list (effects copy).

## Follow-up: undefined Pass buttons at duelResolveManeuver_01165

User saw `undefined Pass` ×3 vs Valeri+Sabre (3 copyable techniques).

**Cause:** PHP switched to `getPropertyArray` (`id`/`name`). Studio still had (or
cached) the old JS that read `technique.Id` / `technique.Name` and put Pass
*inside* the forEach → each technique = button labeled `undefined` + a Pass.

**Fix:** Args include both casings (`id`/`Id`, `name`/`Name`). JS uses
`id ?? Id` / `name ?? Name`, Pass once outside the loop. Redeploy PHP alone is
enough for labels if old JS remains; redeploy JS for single Pass.
