# The Boar's Guile (01125) Audit

## Card Text
**Scheme:** You may add a Renown to any location. If you do not, move a Renown to an adjacent location.

Choose an enemy character. When the chosen character is your adversary, your combat cards gain +1 thrust.

**Reaction:** At the beginning of Dusk, if the chosen character is at Home - Gain a Renown.

## Scheme Resolution Flow - OK
Four-state flow:
- State 01125: Player picks a location to add Renown, or passes
- State 01125_2 (if passed): Player picks a location to move Renown FROM (must pick if any location has renown)
- State 01125_3: Player picks an adjacent location to move Renown TO (adjacency enforced on frontend via `getListOfLocationsAdjacentToLocation`)
- State 01125_4: Player chooses an enemy character (must choose if any exist; Pass only enabled when no enemies)

All transitions correct. Backend validates renown exists before allowing move in state 2. Frontend disables Pass in state 4 when enemies exist.

## Thrust Bonus - OK
`EventDuelCalculateCombatCardStats` handler checks:
- Scheme is at LOCATION_PLAYER_HOME (in play)
- Duel opponent has ADVERSARY_OF_YEVGENI condition
- Adds +1 thrust

## Dusk Reaction - Bug Found and Fixed

**What:** `removeCondition(Game::ADVERSARY_OF_YEVGENI)` was called without `updateCardObjectInDb()`. The frontend was notified via `yevgeniAdversaryRemoved`, but the DB was not updated.

**Impact:** On page refresh after dusk, the adversary condition marker would reappear on the character since the DB still had it. This is inconsistent with the frontend state.

**Why this pattern matters:** In BGA, each PHP request rebuilds state from DB. In-memory changes without DB persist are lost. The `addCondition` call in `actFromCardWithId` (state 4) correctly calls `updateCardObjectInDb` - the removal just missed it.

**Fix:** Added `$game->updateCardObjectInDb($character)` after `removeCondition`.

**Note on condition lifecycle:** The adversary condition is set during scheme resolution and removed at dusk begin. Since all schemes go to the locker at end of day via `stDuskPhaseCleanup()`, the condition only needs to last one day. The dusk begin handler correctly removes it regardless of whether the character is at home (renown is only gained if at home, but the condition is always cleaned up).

## Frontend - OK
- State 1: All city locations selectable, confirm + pass buttons
- State 2: Only locations with renown selectable, pass disabled if any exist
- State 3: Only adjacent locations selectable (uses `getListOfLocationsAdjacentToLocation`)
- State 4: Only enemy characters selectable, pass disabled if any exist
