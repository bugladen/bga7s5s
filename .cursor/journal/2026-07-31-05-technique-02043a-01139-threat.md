# Technique_02043a + Maneuver_01139 — wrong ending threat / confusing technique column

## Repro

Miyato (_02043, Combat 3) takes 3 incoming threat, plays Strength of Ten (_01139: R2/P1/T0), activates Maneuver_01139 (+3 Thrust), then Technique_02043a (copy maneuver).

Expected adversary threat: 2 (riposte) + 3 (maneuver) + 3 (copy) = 8.
Observed: Maneuver column Thrust 6, Technique column Thrust 3, ending adversary threat 5.

## Root cause (WHY ending is 5)

Technique_02043a currently does BOTH:

1. **Technique channel copy** (April 2026 design): reads `maneuver_*` from DB, adds them again via `EventDuelCalculateTechniqueValues`.
2. **Clone + CalcManeuverValues** (May 2026 addition for stateful maneuvers like 01135): queues Activated → Resolve → Calc for a clone on Miyato.

Event order when technique is chosen (`actDuelTechniqueChosen`):
Activate → ResolveTechnique (queues clone events) → CalcTechniqueValues → then clone Activated/Resolve/CalcManeuver.

`updateRoundWithCombatStats` mode `maneuver` recalculates ending threats from `combat_* + event only` — it does **not** include already-stored `maneuver_*` or `technique_*`. Designed for one maneuver calc per round.

So final clone CalcManeuverValues recomputes as combat(R2/P1/T0) + clone event(+3T) → adversary threat 5, **wiping** both the original maneuver and the technique-channel contributions. Meanwhile columns accumulate: maneuver_thrust 3+3=6, technique_thrust=3. Display looks like triple counting; ending threat is single-maneuver.

May journal claimed triple-count concern was "overstated or fixed" — it was not. Mode maneuver still overwrites.

## Fix plan

1. **DB.php**: mode `maneuver` and `technique` both sum `combat_* + stored maneuver_* + stored technique_* + event`. WHY include technique in maneuver mode: clone Calc fires *after* technique calc; must not wipe prior technique R/P/T. WHY include stored maneuver in maneuver mode: second maneuver calc (clone / Katain) must stack. Same for technique mode + stored technique (multi-technique same round).

2. **Technique_02043a**: remove technique-channel R/P/T copy (`copiedRiposte/Parry/Thrust` + `EventDuelCalculateTechniqueValues` handler). Keep clone + CalcManeuverValues as the sole value path. WHY: copy-the-effects means the clone re-applies the maneuver (including Maneuver_01139 reading actor Combat again). Technique column stays 0 — answers Eddie's "can technique value not show". Delayed/non-RPT effects still via clone Resolve/EndOfRound.

## Implemented

- `DB.php`: SELECT now includes `technique_*`. Both maneuver and technique modes sum combat + stored maneuver + stored technique + event.
- `Technique_02043a`: removed `copiedRiposte/Parry/Thrust` and the `EventDuelCalculateTechniqueValues` handler. Clone Activated→Resolve→CalcManeuverValues remains.

## After-fix expected display (01139 case)

- Combat: R2 P1 T0
- Maneuver: T6 (original +3 + clone +3)
- Technique: T0 (technique still listed by name when activated; no RPT chips inflated)
- Ending adversary threat: 8

## Do not regress

Do NOT re-add technique-channel RPT copy "for display symmetry" while clone Calc still fires — that was the dual-path mess.

Do NOT revert maneuver mode to `combat + event only` — May 2026 journal was wrong that multi-maneuver calc was safe.

## Not doing

Hiding zero technique chips / skipping CalcTechniqueValues notify when RPT are 0 — out of scope; 0 is enough to stop the confusion.
