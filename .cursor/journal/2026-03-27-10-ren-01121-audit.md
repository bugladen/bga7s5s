# Ren (_01121) Audit

## Card Text
> While Ren's adversary controls equal or more characters than you, her adversary's combat cards have -1[parry]. (Anything less than 0 is treated as a 0.)

## Files Audited
- `modules/php/cards/_7s5s/_01121.php` (main class — Character)
- `modules/php/theah/events/EventDuelCalculateCombatCardStats.php` (event class, removeParry method)
- `modules/php/StatesTrait.php` (stApplyCombatCardStats — event creation)
- `modules/php/theah/Theah.php` (getCharactersInPlayByPlayerId, getDuelOpponentId)
- `modules/php/theah/EventHub.php` (event dispatch loop)
- `modules/php/cards/Character.php` (parent handleEvent)

## Analysis

### Trigger: `adversaryId == $this->Id`
In `EventDuelCalculateCombatCardStats`, `actorId` = character playing the combat card, `adversaryId` = their opponent. When `adversaryId == Ren`, the actor is Ren's adversary, and the event is calculating that adversary's combat card stats. This correctly targets "her adversary's combat cards." ✅

### Condition: character count comparison
- `$actor` = Ren's adversary (the actorId character)
- `$adversaryCount` = characters in play controlled by adversary's player
- `$characterCount` = characters in play controlled by Ren's player
- `$adversaryCount >= $characterCount` matches "controls equal or more characters than you" ✅

### Effect: removeParry(1)
`removeParry` checks `if ($this->parry > 0)` before subtracting, preventing negative values. The `parry` property uses `private(set)` so it can only be modified through the class methods. Since `removeParry(1)` from a positive value produces at minimum 0 (from 1-1=0), the floor behavior is correct. Matches "(Anything less than 0 is treated as a 0.)" ✅

### Per-card application
`stApplyCombatCardStats` creates a fresh `EventDuelCalculateCombatCardStats` for each combat card played. Ren's handler runs for each event, so every combat card the adversary plays is affected. ✅

### "While" semantics
Condition is evaluated each time the event fires — proper continuous/passive ability. ✅

### Event processing order
`runEventHubAfterCards = true` means card handlers run before the EventHub. Base stats (from the combat card's printed values) are set on the event before queueing. By the time card handlers process it, base parry is already populated. No ordering concern for the typical case.

### No auxiliary files
Only `_01121.php` exists. No reactions, techniques, or maneuvers needed for a passive ability. ✅

## Verdict
No issues found. Implementation correctly captures the card text functionality.
