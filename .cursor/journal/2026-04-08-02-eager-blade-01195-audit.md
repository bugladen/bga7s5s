# Eager Blade (01195) Audit

## Card Text
> **Forced:** After this card enters a discard pile • Add it to [The Grand Bazaar].
> When the equipped character plays a combat card, destroy this card and gain +1 [Riposte].

## Verdict: No Bugs

### Forced ability — discard-to-bazaar chain
- Listens for `EventCardAddedToCityDiscardPile` where `$event->cardId === $this->Id`. Correct event — CityAttachments always go to the city discard pile, never a player discard.
- Queues `EventCityCardAddedToLocation` to move card to `LOCATION_CITY_BAZAAR`. The EventHub handler for that event properly sets `$card->Location`, calls `$deck->moveCard()`, and notifies.
- `runEventHubAfterCards = true` on `EventCardAddedToCityDiscardPile` means card handlers fire first, so Eager Blade queues the bazaar-move event before the EventHub finalizes the discard. The bazaar-move then processes afterward. Ordering correct.
- No infinite loop risk: the bazaar-move event doesn't trigger a discard.

### Combat card trigger — destroy + riposte
- Listens for `EventDuelCalculateCombatCardStats` with `$this->isAttached() && $this->AttachedToId == $event->actorId`. This correctly matches "when the equipped character plays a combat card" — `actorId` is the character playing the combat card that round.
- Adds +1 Riposte via `$event->addRiposte(1)`. Respects dashed riposte (won't add if dashed). The destruction still happens regardless of dashing — this is correct per the card text (both effects are mandatory).
- Destruction: unequip event → discard to city discard pile. Standard pattern for destroying equipped attachments. `$asEffect = true` because the destruction is an effect (no cost bullet in the text).
- The chain works: destruction sends card to discard pile → Forced ability fires → card moves to bazaar. The card recycles itself.

### Constructor
- Stats: CombatModifier +1. Matches card.
- Traits: Corruption, Weapon, Melee, Sword, Unique. Correct.
- WealthCost: 1. Correct.

### Considered edge cases
- **Double-trigger**: If the character plays two combat cards somehow, the first trigger destroys Eager Blade. On the second, `isAttached()` returns false, so no double-trigger.
- **Explanation text with dashed riposte**: Adds "+1 Riposte" explanation before the `addRiposte()` dashed check, so both the "+1 Riposte" and "Value is dashed" messages appear. Cosmetically slightly confusing but consistent with codebase pattern (_01122 does the same thing). Not a bug.
- **`===` vs `==`**: The Forced ability uses `===` for `$event->cardId === $this->Id` while the combat trigger uses `==` for `$this->AttachedToId == $event->actorId`. Both are int-to-int comparisons so both work. Not a bug.
