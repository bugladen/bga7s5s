# Ekaterina Ilyanava (_03049) — create-character

## Card text
1. After Ekaterina's location is claimed, she may move to a different City location.
2. When an opponent collects Renown from this location, they collect one fewer. (Remaining Renown stays.)
3. Technique: +1 Parry. You may engage an Artifact equipped to Ekaterina for +2 Parry instead.

## Context
Continuing FAF after Wily (_03048). Scaffold was a bare Leader shell with Usurra typo.

## Approach / WHY

### Claim-move — Continuous Reaction (Reaction_03049)
Unlabelled "After … may …" → Continuous Reaction like Angeline `_03025` (no `setUsed(true)`, hook-satisfying comment).

Trigger: `EventLocationClaimed` when `event.location == owner.Location` — **any** claimer. Competitive notes: "All claim effects [for either player]"; Tomoe end-of-HD claim + move is the degenerate line.

Effect: Pattern D city-destination buttons (`Reaction_03040` Soline), `engage=false`, Pass declines without burning.

### Renown denial — card-local eventCheck + put-back
PlayerGainsReknown has **no location field**. Two Collect pipelines:

1. **Plunder** (`stPlunderGainRenown`): Take → Gains → Removed, amounts = `$location->Renown`. Handle via `EventPlayerTakeReknownForControlledLocation` (has location+player) arming reductions on Gains + Removed.

2. **Direct Collect** (Sanjay-style): Removed → Gains. Arm on opponent Removed from her location; confirm on immediately next matching Gains; put 1 Renown back in `handleEvent` on that Gains (Removed already queued at full amount — can't rewrite it).

WHY not reduce every opponent Removed: Renown *Moves* also emit Removed+Added. Reducing those would destroy moved renown. Arm cleared if any non-confirming eventCheck intervenes.

WHY put-back in handleEvent not eventCheck: Add must run after full Removed applies.

### Technique — choice state only when Artifact available
Base +1 needs no Artifact (`isAvailableToPlayer` = in-duel actor only).

- No unengaged Artifact → Resolve sets `ParryBonus = 1`, Calculate applies.
- Has Artifact(s) → `createTechniqueTransitionEvent("03049")` (HIGHEST_PRIORITY before Calculate). Choice: id 0 = +1, attachment id = engage + +2. Mirror Katain `Technique_02011` engage picker + Maneuver_03024 id buttons.

State: `DUEL_CHOOSE_TECHNIQUE_03049 = 52103049`, JS in OnUpdateActionButtons.faf.js.
