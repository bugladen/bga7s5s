# _01126 Claim Guard

Eddie asked to give Leshiye of the Wood (`_01126`) the same location-claim guard pattern as Indomitable Will (`Action_01130`) and to add an upgrade backfill analogous to `backfillIndomitableWillFlags`.

## Decision

Replace `_01126`'s `EventLocationClaimed` exception with the persisted `CityLocation->CanBeClaimed` flag. WHY: claim events can be produced during server-side event processing, where a card-level `eventCheck` exception can leave the state machine half-finished. The established emit-site guards safely suppress the claim before such an event is queued.

The scheme will disable claiming when it moves into the city and restore claiming when it is sent to the Locker. A build-time backfill will detect active `_01126` cards and repair the flag for games saved before this behavior existed.

There is a transient ordering concern when Leshiye removes an Indomitable Will character: that character's cleanup can restore the flag after Leshiye disables it. The build-time backfill deliberately runs on every fresh `Theah` build, so the flag is repaired before the next player request can submit a claim.

## Result

Implemented the flag lifecycle in `_01126`, removed its `EventLocationClaimed` import/check, and added `Theah::backfillLeshiyeOfTheWoodFlags()`. The backfill requires both a non-empty `ChosenLocation` and the card's current location to match it; WHY: a stale chosen-location property on a card outside the city must not permanently block that location.

PHP lint passed for `_01126.php` and `Theah.php`; IDE diagnostics and `git diff --check` were also clean. Wrote Eddie-facing output to `_results/2026-07-17-01126-claim-guard.md`.
