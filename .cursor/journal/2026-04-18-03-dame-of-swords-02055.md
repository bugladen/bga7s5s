# Dame of Swords (_02055) Implementation

## Card Text
> **Technique:** Copy the effects of a **Technique** on your participant or one of their attachments. Sink this card.

Neutral FactionAttachment. Trinket/Card/Relic/Unique. WealthCost 0. DashedRiposte, Parry 2, Thrust 3.

## Design Decisions

### Copy Technique Pattern — Based on Maneuver_01165 (I Know that Trick!)
Both cards copy a technique. Key differences from _01165:
- _02055 is a **Technique** on an attachment (not a Maneuver on a Risk card)
- Copies from **own participant** (not the adversary)
- **Sinks** the card after use (the Risk card stays in play)

The flow: `EventResolveTechnique` → transition to pick state → player picks technique → clone, add to actor, fire technique events, sink card.

WHY clone-and-add pattern: The technique needs to fully resolve (including complex techniques that have their own states, like _02054's wound choice). Simply applying combat values wouldn't handle interactive techniques correctly.

### The Sink-and-Cleanup Problem
When Dame of Swords sinks (moves to faction deck), `buildCity()` no longer loads it. Its technique's `handleEvent` won't receive `EventDuelNewRound` or `EventDuelEnd`. So the copied technique on the actor character would never get cleaned up.

**First approach (rejected):** Dual-track cleanup with a game global `COPIED_DUEL_TECHNIQUES` and a `cleanUpCopiedDuelTechniques()` in StatesTrait called before EventDuelNewRound/EventDuelEnd. This worked but leaked card-specific logic into shared framework code.

**Final approach:** Added `IsTemporaryCopy` flag to the base `Technique` class. The copy sets this flag to true. Since the copy lives on the actor character (which IS in the game world), it receives events normally. The base class handles self-removal on `EventDuelNewRound` (per-round, matching 01165's behavior) and `EventDuelEnd` (safety net). Self-contained, no framework changes needed.

WHY this is better: The copy manages its own lifecycle. No globals, no StatesTrait changes, no Game.php changes. The `IsTemporaryCopy` flag defaults to false so existing techniques are unaffected.

### Self-Reference Filter
The `getAvailableTechniques` method filters out this technique's own ID to prevent copying itself. WHY: Dame of Swords IS an attachment on the participant, so its technique would appear in the list. Copying a "copy technique" technique would be nonsensical.

### No Pass Option
The state doesn't include a pass/skip option. WHY: The card text says "Copy the effects" (mandatory). The `isAvailableToPlayer` check ensures there's at least one copyable technique before the technique appears as an option.
