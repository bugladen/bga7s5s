# Action_03040 CanBeClaimed Availability Gate

Eddie: Action_03040 needs to check `theah->canLocationBeClaimedBy` in order to be used.

## Decision Before Edit

Same claim-gate sweep as 01143 / 01141 / 01075 today. Resolve path already used
`canLocationBeClaimedBy` for claim UI/emit and for "any payoff?" branching after pressure
success. Availability only required city + unengaged + Finesse pressure — so Soline's
action could still be offered when the location was unclaimable AND no unengaged opposing
character existed (dead engage + pressure).

WHY not require claimability alone: card text is "claim it or engage an opposing
character". Forcing `canLocationBeClaimedBy` as a hard availability requirement would
hide a still-useful engage-only pressure. Mirror the existing EventLocationPressureResult
gate: available iff `canClaim || count(engageable) > 0`.

WHY `canLocationBeClaimedBy` not `$location->CanBeClaimed`: central API, `$playerId`
reserved for future per-player claim rules.
