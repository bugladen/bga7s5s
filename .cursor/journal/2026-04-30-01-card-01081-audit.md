# Card _01081 (Gallant Deeds) Audit

Card text: "City Action: Target an opposing engaged character • That character and your performer both en garde."

## Audit results

`Action_01081` largely matches the text:
- Performer filtered to Engaged (`getPerformersForAction`)
- Target validated: opposing controller, same location as performer, must be Engaged
- En garde events queued for both performer and target

## Bug found and fixed

`isAvailableToPlayer` looped over *all* player characters in city and returned true if any was at a location with an opposing engaged character — without requiring the player's own character there to be Engaged.

WHY this is wrong: Performers are filtered to Engaged, so the action could be flagged "available" when no valid performer/target pair actually exists (e.g., player's engaged characters are at locations with no opposing engaged, while non-engaged friendly is at a location with one).

Fix: added `if (! $character->Engaged) continue;` inside the loop so the availability check matches the performer eligibility.

## Notes for next session

Did NOT alter the en garde queueing — both events fire even if the target was already non-engaged on the way through, but the target must be Engaged at validation time so that's fine. Performer must be engaged via `getPerformersForAction` filter, so we won't en garde a stalking/already-en-garde performer.
