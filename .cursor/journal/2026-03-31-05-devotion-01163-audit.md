# Devotion (_01163) Audit

## Card Text
> Action: Look at the top three cards of your deck. Sink one, put one into your hand, and add the last to a location facedown. At the end of the day, if you control that location, put the added card into your hand. Otherwise, discard it.

## Result: All Correct — One Dead Code Cleanup

The implementation spans 6 files and correctly captures all aspects of the card text.

### Files Reviewed
- `_01163.php` — Card definition (Risk with Faith trait, Wealth 1)
- `Action_01163.php` — Action logic, handles the 3-state flow
- `_01163_CardClone.php` — Clone card for the facedown placement + end-of-day resolution
- `State_highDramaPhase01163.php` — State 1: choose card to sink
- `State_highDramaPhase01163_2.php` — State 2: choose card for hand
- `State_highDramaPhase01163_3.php` — State 3: choose location for remaining card

### How It Works

1. `handleEvent` grabs top 3 from faction deck, stores IDs in `REVEALED_CARDS`
2. State 01163: player picks a card → `insertCardOnExtremePosition(false)` = bottom of deck (sink)
3. State 01163_2: player picks a card → `createCardAddedToHandEvent`
4. State 01163_3: player picks a city location → original card moved to PERMANENTLY_HIDDEN, a `_01163_CardClone` created at the location with `FaceDown = true`, `CardMusteredEvent` fired
5. Clone listens for `EventDuskPhaseBegin` → checks if controller controls the location:
   - Yes: clone hidden, original card added to hand
   - No: clone hidden, original card moved to controller's discard pile

### Fix Applied
Removed dead code on line 55 of `_01163_CardClone.php`. The else branch fetched `$clonedCard` via `getCardById` but never used the value before reassigning it on line 73 via `getCardObjectFromDb`. Only the DB fetch is actually needed (for the discard notification data).

### Architecture Notes

WHY the clone approach: Same pattern as _01106 and _01124. A facedown placeholder needs to exist visually at the location. The original card can't be placed there directly because it would need to be hidden/revealed at end of day and the card framework needs a distinct object at the location. The clone holds `ClonedCardId` (the original) and `ParentCardId` (the Devotion risk card) for resolution.

WHY `EventDuskPhaseBegin` for "end of the day": Confirmed consistent with _01125 (Yevgeni's scheme) which also uses `EventDuskPhaseBegin` for end-of-day effects. Dusk is the correct phase.

### Edge Cases Not Guarded
- If deck has fewer than 3 cards, `getCardsOnTop(3)` returns fewer. The 3-state flow still runs but with fewer choices. No guard exists in `isAvailableToPlayer`. This is an edge case that would be very rare in normal play (deck is usually large).
