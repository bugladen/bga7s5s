## WHYs that will look like bugs
- **Empty ModifiedTraits.** `hasTrait` copies `Traits` back when `ModifiedTraits` is empty. Removing the last trait does not stick. Add a leftover trait first (Action_03011 Scoundrel, Maneuver_03024 Hero, Technique_03018 Hero).
- **PayStateType 0 is the in-hand ACTION branch.** Reaction_03013 turn-end zeroes pay type and sets Used. The next `handleEvent` does not restamp while Used. `activate` then calls `calculateInHandPayDiscount` with 0 and fatals on a null action. Tests set `Used = false` before the next offer so the reaction pay type is stored again.
- **Maneuver_03022 En Garde.** `if ($character->Engaged)` queues `EventCardEngarded`. Else it notifies "already En Garded" and queues nothing. En Garde clears Engaged. Pass throws while anyone is still at the snapshotted `DuelLocation`. `getDuelOpponentId` ignores its argument and returns `duelOpponent` — set that to the participant who might be destroyed.
- **`_03014` Techniques is protected** (TechniqueTrait). Use `getTechniques()`. Character implements `IHasTechniques`, so `placeCharacter`/`setId` does wire OwnerId. The old note that Kaspar does not implement the interface is wrong.
- **`_03018` grants any wounded Character.** There is no harness character that fails `instanceof IHasTechniques`. A wounded `GenericCharacter` gains Technique_03018. Wound-event grant does not look at `Wounds` (handler order). Resolve sync does (`Wounds > 0`), and skips dying. Scheme must be Home for wound/heal, not for resolve. `EventResolveScheme` must have `theah` set or the notify fatals.
- **EventCardMoved vs Location.** Handlers and reaction buttons that read `owner->Location` see the pre-move location. Write Location to the destination before `performReaction` (Reaction_03025). `_03026` influence counts a card moving in from the event and excludes a card moving out that is still listed. Queued influence events are not applied — write `ModifiedInfluence` before asserting the drop.
- **Reaction_03020** deletes the add/remove events that share the moving event's batch, and only after `EventRiskReactionTriggered` (post-pay). `batchId > 0` required. Cancel stacks pay ahead of those events. Decline resets saved state and does not pay. Moving event is informational.
- **Action_03021** engages at announce, before ActionTriggered, so a cancel of the trigger still leaves the engage. Trigger sets `CORNERED_CHALLENGE_TYPE` and does not resolve the action. Refuse/intervene live on the card. Wound `abilityId` is `(string) $card->Id`.
- **Action_03026** is not city-only. Home is a legal origin (`includeHome` false is the destination). Discard is `asEffect` (not payment, not played). Sorcery discard plus an opponent at the NEW location opens step 3 and does not resolve yet. Otherwise resolve on the move. Wound step uses current Location, which the queued move has not updated.
- **Reaction_03027a** any non-pass id spends, and heals if wounded, even when the Renown location fails the recheck. Pass returns before `setUsed`.
- **Reaction_03027b** a choice that fails the Duelist/adjacent recheck does not spend. Home is not an adjacent city.
- **`_03028` combat ban is `eventCheck`.** The method itself does not look at Fate's Silence (Theah skips the call). Duel Combat=Influence only at Grand Bazaar. Restore queues only when `ModifiedCombat` differs from the stored value — apply the queued combat before asserting the restore, and clear the queue before the "not the bazaar" check or the restore event is still sitting there.
- **Action_03029** mode 1 resolves immediately (sorcery start, wound performer, move, sorcery played, action resolved). Mode 2 only stores `CHOSEN_CARD`. Mode constants are private; tests use 1 and 2. MoveMode 0 is "invalid move option".
- **Action_03030** stores the Diplomat in `CHOSEN_CARD` because `CHOSEN_PERFORMER` becomes the Duelist. Challenge type is set on the target step, not the trigger. Transition `03030_2` sourceId is the duelist. No action resolved on the action. Threat +1 only when `CHALLENGE_TYPE` is sworn swords. Resolve on the card opens the picker; it does not add Renown.
