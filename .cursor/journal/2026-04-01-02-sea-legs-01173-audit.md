# Sea Legs (_01173) Audit

## Card Text
> Reaction: After your character moves to a City location • Move them again to an adjacent City location.

Risk card, WealthCost=1, Riposte=1, Parry=0, Thrust=1, Savvy trait. Uses the in-hand payment flow (card played from hand, player pays wealth, then effect resolves via EventRiskReactionTriggered).

## Bug 1: Missing setUsed() call

`Reaction_01173::performReaction` never called `$this->setUsed($game->theah, true)`. Every other reaction in the codebase calls this when the player accepts (except Reaction_01040 which explicitly comments why it skips it). 

WHY this didn't cause an obvious infinite loop: The trigger checks `$owner->Location == Game::LOCATION_HAND`, and after payment the card moves from hand to discard. So the second move's EventCardMoved can't re-trigger the reaction. But `setUsed` is still needed for proper state tracking and consistency.

Note: `Reaction_01088` and `Reaction_01023` also appear to be missing `setUsed` with the same payment flow pattern. Didn't fix those — they're separate cards. Worth checking in a future audit pass.

## Bug 2: Missing server-side adjacency validation

In the `EventRiskReactionTriggered` handler, the code validated `locationInCity($location)` but did NOT validate that the location was adjacent to `$this->ToLocation`. The buttons generated by `getReactionButtonProperties` only show adjacent locations, but a crafted client request could send any city location string. Added `in_array($location, $adjacentLocations)` check.

## Verified Correct

- **Trigger**: `EventCardMoved` (not `EventCardMoving`) matches "After your character moves" — correct past-tense/completed-action trigger
- **Ownership check**: `$card->ControllerId == $owner->ControllerId` correctly enforces "your character"
- **City location check**: `locationInCity($event->toLocation)` correctly limits to City locations
- **Hand check**: `$owner->Location == Game::LOCATION_HAND` correctly requires the card to be in hand
- **Character check**: `$card instanceof Character` ensures only characters (not other card types) trigger this
- **Adjacent destinations**: `getAdjacentCityLocations($this->ToLocation, false)` correctly excludes Home (not a "City location")
- **engage=false on second move**: The character keeps their current engaged state. Since they were just engaged by the first move, they stay engaged. This prevents unintended re-engagement side effects while preserving the character's state.
- **Payment flow**: EnteringPayState → ReactionPayTransition → EventRiskReactionTriggered. Standard in-hand reaction payment pattern.
- **Constructor** (`_01173.php`): WealthCost=1, Riposte=1, Parry=0, Thrust=1, Savvy trait. All correct.
