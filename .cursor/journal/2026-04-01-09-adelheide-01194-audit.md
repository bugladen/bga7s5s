# Adelheide Schmidt (_01194) Audit

## Card Text
> Negotiable (You may parley when paying for this card.) City Action: Discard an attachment • Wound target opposing character.

City character. Resolve=4, Combat=2, Finesse=2, Influence=0 (dashed). WealthCost=4, CityCardNumber=18, Negotiable. Traits: Mercenary, Eisen. Implements `IHasActions` with `Action_01194`.

## Result: No bugs found

The implementation correctly captures all card text functionality.

### Verified Correct

**Negotiable**: `$this->Negotiable = true;` set in constructor.

**City Action**: `isAvailableToPlayer` checks `$theah->cardInCity($adelheide)`.

**Discard an attachment (cost)**:
- Availability: `count($adelheide->Attachments) == 0` returns false if no attachments
- State 01194: shows attachment buttons via `getArgsFromAction`, player picks one
- On resolution: `EventAttachmentUnequipped` then `EventCardAddedToCityDiscardPile` with `$asEffect = false`

**Wound target opposing character (effect)**:
- Availability: filters `getCharactersAtLocation` by `ControllerId != adelheide->ControllerId`. Since `getCharactersAtLocation` already excludes uncontrolled characters, this is functionally identical to `getOpposingCharactersAtLocation`.
- State 01194_2: opposing characters at Adelheide's location made selectable
- On resolution: `EventCharacterBeingWounded` with 1 wound, sourced from Adelheide, passing `$this->Id` as abilityId
- `isValidTargetForAbility`: validates target is opposing and at same location

**IAbilityThatTargetsCharacters**: correctly implemented, enabling reactions to fire.

**Event flow**: All three events `eventCheck`ed then `queueEvent`d in order (unequip → discard → wound). Compared with Sibella (01012) which has a similar "wound target opposing character" pattern — Sibella skips `eventCheck` and wraps in sorcerer ability events. Adelheide's approach uses eventCheck which allows reactions to prepare for all three events before processing, which is valid.

**Notification**: Custom message `'${player_name} uses Adelheide Schmidt's Action to wound ${character_name}.'` instead of `announceAction()`. Functionally equivalent, just a different notification style.

**JS handlers**: All correct — OnEnteringState highlights Adelheide, OnUpdateActionButtons shows attachment buttons (state 1) and confirm button (state 2), OnLeavingState cleans up highlights.

**Zombie handling**: Both states in ZombieTrait with `nextState("pass")`. Note: neither state has a "pass" transition defined — this is a systemic pattern across many card-specific states (01185, 01197, 01205, etc.) and not unique to 01194.

## Design Observations

- Location restriction on targets is implicit (standard for City Actions in this game), matching how Sibella and other "target opposing character" cards work.
- The two-step UI flow (select attachment, then select target) is clean. Attachment selection through buttons rather than card clicking makes sense since attachments may not be independently visible cards on the board.
