# Gold or Steel (_02038) — Maneuver Implementation

## Card Text
- **Pirate Maneuver:** If your participant has more [Combat] than the adversary - Draw a card unless the adversary suffers a wound.
- **Duelist Maneuver:** If your participant has more [Finesse] than the adversary - Draw a card unless the adversary suffers a wound.

## Implementation

Both maneuvers share identical resolution logic, differing only in trait gate (Pirate/Duelist) and stat comparison (Combat/Finesse). Used a single `Maneuver_02038` class parameterized by `$requiredTrait` and `$statType`, instantiated twice in the card constructor. Pattern mirrors `Maneuver_02009` (Murder) which does the same parameterization for Thug/Duelist/Spy.

### "Unless" Semantics — Adversary Chooses
"Draw a card unless the adversary suffers a wound" = adversary picks: suffer a wound (preventing the draw) or let the controller draw (no wound). This is the standard CCG "unless" interpretation where the subject of the "unless" clause controls the choice.

Implemented via `createTransitionEvent` targeting `$adversary->ControllerId`, which makes the adversary the active player in the `duelResolveManeuver_02038` state. Two buttons: "Suffer a Wound" (id=1) and "Let Opponent Draw" (id=2).

### Stat Comparison — Strict Greater-Than
Card says "more [Combat] than the adversary" — used strict `>` not `>=`. This matches `Technique_02021` pattern (Influence > adversary Influence) and `Maneuver_01079` (Finesse > adversary Finesse). Used `ModifiedCombat`/`ModifiedFinesse` for the comparison since those reflect attachments and in-duel modifiers.

Used `match` expression on the stat type string to avoid dynamic property access.

### Zombie Behavior
Zombie in the choice state just calls `nextState()` without applying either outcome. This matches `State_duelResolveManeuver_01110` pattern. Neither wound nor draw occurs — effectively a no-op skip.

### Notification Messages
Used adversary's `ControllerId` for `player_name` in notifications since the adversary is the one making the choice. This differs from `Maneuver_01110` which uses the maneuver owner's player name — I think 01110 might be slightly off there, but it's a minor log detail.
