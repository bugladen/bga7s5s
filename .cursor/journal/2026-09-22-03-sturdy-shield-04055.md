# Sturdy Shield `_04055`

## Context
Continuing BAS Neutral attachments after Sabre `_04054`. Offhand Armor/Shield with Combat-threshold equip and two Parry Techniques (one engage, one Gambling).

## Classification
1. Offhand → `$this->OffHand = true` (no ability class)
2. May only equip to your character with 2[Combat] or more → Pattern A stat-threshold (`ModifiedCombat >= 2`), dual-gate like Spaulders `_04053` (Finesse sibling)
3. `<b>Technique:</b> Engage this card • +1[Parry]` → Pattern E — copy Pompon `Technique_04026`
4. `<b>Gambling Technique:</b> +1[Parry]` → Pattern E + Gambling gate (`IN_DUEL` + `DUEL_GAMBLED` + actor==owner); Calculate `parry += 1`

## Mirror choice / WHY
- Equip: `_04053` shape with `ModifiedCombat` instead of `ModifiedFinesse`. WHY Modified not printed base — same as Spaulders / skill Pattern A.
- Engage half: full copy of `Technique_04026` as `Technique_04055a`. Considered reusing 04026 via setId — rejected; ClassId would still be Technique_04026 and confuse debugging / uniqueness on the card. Sabre used setId only for the *generic* PlusOneThrust.
- Gambling half: custom `Technique_04055b` rather than `Technique_PlusOneParry` + setId. WHY: PlusOneParry only gates `IN_DUEL`, not `DUEL_GAMBLED`. Extending PlusOneParry and overriding availability would work but duplicates Name/Calculate and still needs the cancel comment — own class is clearer next to 04055a.
- Do **not** treat the Gambling keyword as making the engage Technique gambling too — they are separate printed abilities.
- Shield trait missing from TraitNames — added alphabetically after Shenzhou.
