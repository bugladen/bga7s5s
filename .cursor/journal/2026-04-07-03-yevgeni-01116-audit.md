# Yevgeni (01116) Audit

## Card Text
1. When Yevgeni plays a combat card, it gains +1 Thrust.
2. Reaction: After Yevgeni's challenge is refused • En garde him.
3. Reaction: While paying for a non-character card • It has -1 cost.

## Verdict: All correct — no fixes needed.

### Ability 1: +1 Thrust on combat cards
`_01116::handleEvent` listens for `EventDuelCalculateCombatCardStats`, checks `actorId == $this->Id`, calls `addThrust(1)`. Same pattern as _01122. The `addThrust` method handles dashed-thrust guard internally.

### Ability 2: En garde after challenge refused
`Reaction_01116a` triggers on `EventChallengeRejected` where `challengerId == yevgeni->Id`. Offers player En Garde / Pass. If chosen, queues `CardEngardedEvent` for Yevgeni and marks reaction used.

### Ability 3: -1 cost for non-character cards
`Reaction_01116b` triggers on `EventEnteringPayState` when player is Yevgeni's controller, card is not a Character, implements IWealthCost, and has cost > 0. Discount provided via all four discount methods (action, reaction, equip, maneuver). IsActive resets on turn end / action resolved / duel round end. Parley and brute costs correctly excluded since those involve characters.

## Minor style note
`Reaction_01116a` calls `$this->IsAvailable()` (uppercase I) while `Reaction_01116b` uses `$this->isAvailable()` (lowercase i). PHP method names are case-insensitive so this is cosmetic only.
