# Quick Reflexes (02059) Implementation

## Context
Continuing Tooth and Claw card implementations. Previous session did Heroic Intervention (02058).

## What Was Done
Implemented Quick Reflexes (02059) - a Neutral Risk card with two abilities:

**Reaction:** When an opponent's ability wounds your character, ignore that wound.
**Maneuver:** If your participant has 3+ Finesse, +1 Riposte.

## Key Decisions

### Reaction: Checking ability ownership via abilityId
User specifically requested checking the abilityId's owner rather than just the sourceId. The flow is:
1. Get source card via `$event->sourceId`
2. Look up the ability via `$source->getAbilityById($event->abilityId)`
3. Get the ability's owning card via `$ability->getOwningCard()`
4. Check that owner's ControllerId differs from reaction owner's ControllerId

WHY this matters over just checking sourceId: In theory, sourceId and the ability's OwnerId should be the same card, but going through the ability lookup is more robust against edge cases where an ability might be associated with a different card than the source.

Also check that abilityId is not empty - wounds from combat (non-ability sources) shouldn't trigger this reaction.

### Reaction: Cancel-and-re-emit pattern
Used the same pattern as Reaction_01140 (cancel movement):
- On BeingWounded from opponent's ability: cancel event, save clone, offer reaction
- Accept: enter pay state, wound stays canceled, setUsed
- Decline: re-emit saved wound event

### Maneuver: Simple stat check + value modifier
Followed Maneuver_02049 pattern (conditional +1 Riposte). Check `$actor->ModifiedFinesse >= 3` in isAvailableToPlayer, add +1 to `$event->riposte` in EventDuelCalculateManeuverValues.

### Pre-commit hook gotcha
The hook checks for the literal string `Location == Game::LOCATION_HAND`. Using the early-return pattern `Location != Game::LOCATION_HAND` doesn't satisfy the grep. Had to restructure to nested positive checks. This is a known constraint from the hook's simple string matching.

### Reaction: Guard against multiple wound events
Added `$this->savedWoundEvent === null` check in the EventCharacterBeingWounded handler to prevent reacting to a second wound event while already holding one. This is needed because `isAvailable()` won't catch it (setUsed hasn't been called yet at that point).

### Bug fix: Duplicate "played" log entry for RiskReactions
When playing a Risk from hand as a Reaction, "{player_name} played {card}" appeared twice in the game log. Two sources:
1. `RiskReaction::getReactionAnnouncement()` → notified at line ~1914 in `actPayForReactionFromHand`
2. `EventCardDiscardedFromHand` with `AsPlayed=true` → EventHub handler

Fix: Removed the announcement notification (lines 1911-1918) from `actPayForReactionFromHand` in FrameworkActionsTrait.php. The EventHub's "played" message is sufficient, and each reaction's `EventRiskReactionTriggered` handler already describes the specific effect. Reaction_01023 was the only override of `getReactionAnnouncement` — its extra context text ("Choose whether interventions...") was redundant since its EventRiskReactionTriggered handler already announces the actual outcome.

WHY not fix in RiskReaction.php instead: The pre-commit hook flags RiskReaction.php because it `extends CardReaction` but doesn't have `$this->setUsed()` or `$this->isAvailable()` (those are in concrete subclasses). Changing RiskReaction.php triggers this false positive. Fixing in FrameworkActionsTrait avoids this issue.
