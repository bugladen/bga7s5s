# Philip Hase (01039) Audit

## Card Text
**City Reaction:** After Philip equips an attachment • Move him to an adjacent location.
**Technique:** If the adversary is engaged and you control a Mercenary at this location • Wound the adversary.

## City Reaction — Correct

### Trigger
`handleEvent` checks `EventAttachmentEquipped` with `$event->characterId == $philip->Id` (Philip specifically) and `cardInCity($philip)` (city-only trigger). Also gates on `$this->isAvailable()` so it fires at most once per day (reset on `EventDuskEndOfDay` by `CardReaction` base). All correct.

### Effect
`getReactionButtonProperties` presents adjacent locations via `getAdjacentCityLocations($philip->Location)` (which includes Home as adjacent — valid per game rules) plus a Pass button. Reactions are inherently optional in this codebase (see pattern: Reaction_01062, Reaction_01053 all offer Pass/Decline). Card text "Move him" without "may" is fine for reactions — the optionality is in choosing to react at all.

`performReaction` builds a `createCardMovingEvent` with `$engage=false` — card says "Move" not "Move and engage". Only calls `setUsed(true)` when the player actually moves; passing leaves the reaction available for the next attachment equip this day. Correct once-per-day-if-used pattern.

## Technique — Correct

### Conditions
`isAvailableToPlayer` checks: in duel → gets Philip as `getDuelRoundActor()` → Mercenary at Philip's location controlled by player → adversary not in discard/locker → adversary Engaged. All match "If the adversary is engaged and you control a Mercenary at this location".

Uses `getDuelRoundActor()` rather than `getOwningCharacter()` — works because technique system only evaluates the acting character's techniques. Slightly implicit but correct. `handleEvent` uses `getOwningCharacter()` for the same purpose — minor style inconsistency, not a bug.

### Mercenary interaction with _01043
The `hasTrait("Mercenary", $philip)` call passes Philip as the query card. Card `_01043` overrides `hasTrait` to return true for "Mercenary" when `$queryCard instanceof _01039`. This is the deliberate Eisen Mercenary synergy mechanic. Works correctly.

### Effect
`handleEvent` re-validates conditions (adversary engaged + mercenaries present) then creates `createCharacterBeingWoundedEvent` with 1 wound. "Wound the adversary" = singular wound. Correct.
