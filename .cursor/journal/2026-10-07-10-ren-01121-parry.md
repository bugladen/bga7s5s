# Ren (_01121) once-per-round Parry across Maneuver/Technique

## Context
Eddie clarified: Ren's passive covers Maneuvers/Techniques that modify the played combat card. If the combat card has 0 Parry and a later Maneuver/Technique grants Parry, Ren should still reduce by 1. Once any source (combat / Maneuver / Technique) has been reduced this round, do not reduce again until the next round when the adversary plays another combat card.

## Prior audit was wrong for this edge
`2026-03-27-10-ren-01121-audit.md` said combat-card-only `EventDuelCalculateCombatCardStats` was enough. That misses:
1. `removeParry` no-ops when Parry is already 0 (and the old code still logged the explanation).
2. Maneuver/Technique Parry is added later on separate calculate events with public `$event->parry`, not via combat-card stats.

## WHY EventHub (not card handleEvent for Maneuver/Technique)
Technique/Maneuver Parry is written during the card foreach by the ability owner. Ren's card may run before that owner in `$theah->cards` order, so a Ren handleEvent on `EventDuelCalculateManeuverValues` / `TechniqueValues` can see Parry=0 even when the Maneuver will add +1. Same pattern as Unravel / Mireli's Revision: apply in EventHub after the card loop, before DB write.

Combat reduction moved to the same hub path (after Unravel +1) so:
- Unravel's +1 is inside the once-per-round window
- one code path for all three sources

## Once-per-round flag
`$ParryReductionAppliedInRound` stores `Game::DUEL_ROUND` only when a reduction actually happened. A 0-Parry combat card does not set the flag, so a later +Parry Maneuver/Technique in the same round still gets the -1. Cleared on `EventDuelEnd`.
