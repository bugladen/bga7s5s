## Passive Ability: Grant "+1 Riposte" to Other Musketeers

### EventCardMoved — All Three Branches ✅
1. **Jean moves**: Removes `Technique_01067` from Musketeers at old location, adds to Musketeers at new location. Correctly checks `!= LOCATION_PLAYER_HOME` for both. ✅
2. **Musketeer moves to Jean's location**: Adds technique. Checks `ControllerId`, `hasTrait("Musketeer")`, `IHasTechniques`. ✅
3. **Musketeer moves from Jean's location**: Removes technique by `getTechniqueByClassId("Technique_01067")`. ✅

### EventCharacterRecruited — WAS MISSING ❌ → FIXED ✅
Compared with `_01063` (Bastien Girard) which has the exact same passive pattern (grant technique to characters at same location). Bastien handles `EventCharacterRecruited`, Jean did not.

**WHY this matters**: When a character is recruited (`EventCharacterRecruited`), the EventHub sets `ControllerId` but does NOT fire `EventCardMoved`. The character was already at the city location; recruitment just assigns ownership. So if a Musketeer sits unrecruited at Jean's location and is then recruited by Jean's controller, no `EventCardMoved` fires and the technique was never granted.

**Fix**: Added `EventCharacterRecruited` handler mirroring Bastien's pattern, filtered for Musketeers and `!= LOCATION_PLAYER_HOME`.

## Jean's Own Technique: Technique_01067

### Thrust/Riposte Choice ✅
- `EventResolveTechnique`: Checks for other Musketeers at Jean's location. If present, queues a `TechniqueTransitionEvent` to offer the choice. If no Musketeers, defaults to +1 Thrust (`UseRiposteInstead = false`). ✅
- `EventDuelCalculateTechniqueValues`: Adds +1 Riposte if `UseRiposteInstead`, else +1 Thrust. ✅
- `EventDuelEnd`: Resets `UseRiposteInstead = false`. ✅
- `actFromTechniqueWithId`: id=1 → Thrust, id=2 → Riposte. ✅

### Challenge Threat ✅
`EventGenerateChallengeThreat` always adds 1. This is correct because during challenges, the technique is always +1 Thrust (Riposte has no challenge value). The JS for `highDramaChallengeActionResolveTechnique_01067` only shows the Riposte button when `this.inDuel` is true, so challenges won't offer the Riposte choice.

### State Machine ✅
Both `HIGH_DRAMA_CHALLENGE_ACTION_RESOLVE_TECHNIQUE_01067` and `DUEL_CHOOSE_TECHNIQUE_01067` states are correctly defined with `argsForState` and `actFromCardWithId`.

## JS Buttons ✅
- `highDramaChallengeActionResolveTechnique_01067`: Shows Thrust always, Riposte only when `this.inDuel`. Correct — Riposte is useless in challenges.
- `duelChooseTechnique_01067`: Shows both Thrust and Riposte. Correct — both are valid in duels.

## Known Limitation (Not Fixed)
When Jean is destroyed/discarded from play (`EventCharacterDestroyed`, `EventCardDiscardedFromPlay`), the Musketeers at Jean's former location keep their technique. These events don't fire `EventCardMoved`. This is the same gap that exists in `_01063` (Bastien) — it's a codebase-wide pattern limitation, not specific to Jean.
