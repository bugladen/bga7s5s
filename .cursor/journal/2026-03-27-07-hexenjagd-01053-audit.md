# Hexenjagd (_01053) Audit

## Card Text
> Forced: When your round ends • Move your participant Home engaged unless the adversary is a Sorcerer.
> Reaction: When a Sorcerer ability targets a card • Wound your performer at that location and cancel the effects.

## Files Audited
- `modules/php/cards/_7s5s/_01053.php` (main class)
- `modules/php/cards/_7s5s/reactions/Reaction_01053.php` (reaction)

## Forced Ability Analysis

The forced ability uses a two-phase pattern:
1. `EventDuelCalculateCombatCardStats` — sets `EscapeDuel = true` when this card is evaluated as a combat card
2. `EventDuelEndOfRound` — if flag is set, moves actor Home engaged unless adversary is Sorcerer

**Verified correct.** Traced the duel flow through `stApplyCombatCardStats()` and `stDuelEndOfRound()` in StatesTrait.php. Key findings:
- `actorId` from the `duel_round` table IS the person who played the combat card (the active player for that round)
- `getDuelRoundActor()` returns this same character from the DB
- `getDuelRoundOpponent()` returns the opponent
- The `$adversary->hasTrait("Sorcerer")` check correctly implements "unless the adversary is a Sorcerer"
- `createCardMovingEvent` with `$engage = true` and `LOCATION_PLAYER_HOME` matches "Move Home engaged"
- Guard `characterIsInDiscardOrLocker($actor)` prevents acting on destroyed characters

Same pattern used by _01169 ("Not Today"), which is a simpler version without the Sorcerer exception.

## Reaction Analysis

Reaction_01053 extends CancelReaction. Triggers on `EventSorcererAbilityStart`:
- Checks `IAbilityThatTargetsCards` interface — correct, card text says "targets a card" not "targets a location"
- Checks `$event->targetId != 0` — ensures there's a specific card target
- Checks `$target->Location != Game::LOCATION_PLAYER_HOME` — intentional design choice (Home is a shared location string, allowing reactions there would create ambiguity about which "Home" the performers are at)
- Gets owner's characters at target's location — matches "your performer at that location"
- Stacks transition event (processed BEFORE Sorcerer ability effects execute)

Cancellation uses:
- `deleteEventsTargetingCard($target->Id)` — removes pending events affecting the targeted card
- `deleteTransitionEventsBySourceId($this->SourceId)` — removes follow-up transitions from the Sorcerer ability source

Wounding uses `createCharacterBeingWoundedEvent` with 1 wound on the chosen performer.

**Verified correct.** No bugs found.

## Minor Observations (not bugs)
- Variable shadowing of `$event` in Reaction_01053 line 92 — harmless since the original event isn't used after that point
- `getDuelRoundActor()` reads from DB rather than using `$event->actorId` from `EventDuelEndOfRound` — consistent with other cards' patterns, so not a deviation
- The Home exclusion on the reaction is undocumented but makes sense given the shared location string architecture

## Verdict
No issues found. Implementation correctly captures the card text functionality.
