# Opulence (_01170) Audit

## Card Text
> Wealth (This card counts as two when discarded to pay costs. Send it to The Locker after paying costs.)
> Action: Discard your hand • Draw a card.

## No Bugs Found

Initially thought the discard events in Action_01170 needed `asEffect = true`, but that was wrong. The `•` separator in C5S card text divides **cost** (left) from **effect** (right). "Discard your hand" is the cost of the action, not an effect. So `asEffect` correctly defaults to `false`. The cards that do use `asEffect = true` (Maneuver_01115, Maneuver_01108a, Technique_01093, Reaction_01135) are discarding cards as part of their **effect**, which is a different scenario.

**WHY this matters**: `Reaction_01099a` triggers when a card is discarded "due to your effect" — it checks `$event->asEffect`. A cost-based discard should NOT trigger that reaction. The original code was right.

## Everything Is Correct

- **Wealth trait "counts as two"**: Driven by the `hasTrait("Wealth")` check used across all payment validation in `FrameworkActionsTrait.php` (at least 6 locations), `Maneuver_01113.php`, `Action_01180.php`, `Action_01167.php`, `Action_01113.php`, and `UtilitiesTrait.php`. The card has `'Wealth'` in its Traits array, so all these checks pick it up automatically.
- **Wealth trait "Send to Locker"**: The `handleEvent` in `_01170.php` correctly catches `EventCardDiscardedFromHand` where `$event->cardId == $this->Id && $event->AsPayment` and queues a `CardSentToLockerEvent`. Only fires when used as payment, not when played for its action (which uses `AsPlayed = true` instead).
- **Action sequencing**: When the risk is played for its action, the framework moves it to purgatory before the action event fires, so `getCardObjectsAtLocation(LOCATION_HAND)` correctly excludes the Opulence card itself from the discard loop.
- **Action discard flags**: Discards from the action correctly use default flags (`asPayment = false`, `asPlayed = false`, `asEffect = false`) because discarding the hand is the **cost** of the action, not an effect.
- **JS-side Wealth handling**: The client correctly uses `item.traits.includes('Wealth') ? 2 : 1` in all payment selection UIs.
- Card stats (Thrust 1, WealthCost 0, Riposte 0, Parry 0), traits (Wealth, Fortune), and base class (Risk with IHasActions/ActionTrait) all look correct.
