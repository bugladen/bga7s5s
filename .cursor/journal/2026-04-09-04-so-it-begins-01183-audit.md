# So It Begins (01183) Audit

## Card Text
> Traits: Brawl, Feud
> During a duel, participants at this location have -1[Parry] on their combat cards.
> Pressures at this location also add [Combat]. (Pressures using Combat do not add Combat again.)

## Two bugs found and fixed

### Bug 1: Duel Parry applied to wrong participant

The `handleEvent` check was `$actor->Location == $this->Location || $adversary->Location == $this->Location`. This is wrong because `EventDuelCalculateCombatCardStats` fires once per combat card played, and it always modifies the **actor's** card stats. If only the adversary is at this location but the actor isn't, the actor's Parry was being reduced incorrectly.

WHY only check the actor: Each duel round alternates who is the "actor" (the one playing the combat card). When the adversary later becomes the actor and plays their card, the event fires again with them as `actorId`, and the check will correctly apply at that time. The OR condition was double-dipping — reducing the actor's Parry on someone else's behalf.

Confirmed by looking at how Yevgeni (_01116) handles the same event: `$event->actorId == $this->Id` — only checks the actor.

**Fix**: Changed condition to `$actor->Location == $this->Location`.

### Bug 2: Misleading pressure notification when Combat already present

`getPressureStats` always added `Game::STAT_COMBAT` and fired a notification, even when Combat was already the starting stat type. While `array_unique` in `Theah::getPressureStats` handled deduplication, the notification "will add Combat to the Pressure" was misleading — the card text explicitly says "Pressures using Combat do not add Combat again."

**Fix**: Added `!in_array(Game::STAT_COMBAT, $pressureTypes)` guard before the add and notification.

## What checks out

- **City Event Card**: Extends `CityEventCard` correctly, traits match (Brawl, Feud) ✓
- **CityCardNumber**: 7 ✓
- **Pressure deduplication**: `Theah::getPressureStats` calls `array_unique()` after collecting all types, so even without the guard, duplicate Combat wouldn't leak through. The guard prevents misleading notifications ✓
- **`cardInCity` check**: Correctly gates the duel handler so the card only applies while in play ✓
- **`removeParry` respects dashed values**: The event method checks `dashedParry` before modifying ✓
- **Parry floor at 0**: `removeParry` only subtracts if `$this->parry > 0` ✓
