# Ussuran Intrigue (_02050) - City Reaction Implementation

## What Was Done

Implemented the City Reaction for Ussuran Intrigue (card 02050), an Ussura Risk card.

**Card ability:** When any player moves or adds any amount of Renown to any location, pressure your performer's location with Influence. You succeed even if tied. If successful, move one of that Renown to their location instead. (Even during Planning.)

## Implementation Details

### Files Changed
- `_02050.php` — Added `IHasReactions`, `ReactionTrait`, and wired up `Reaction_02050`
- `Reaction_02050.php` (new) — The reaction class
- `Game.php` — Added `USSURAN_INTRIGUE_PRESSURE_TYPE = 4096` (next binary flag after 2048)
- `UtilitiesTrait.php` — Added the new pressure type to the tie-wins check block

### Design Decisions

**Trigger:** Listens on `EventReknownAddedToLocation` which covers both adds AND moves (the event has an `isMove` flag, but we don't filter on it since the card text says "moves or adds").

**Performer selection:** Player chooses from their characters in the city, filtered to only show characters at locations DIFFERENT from the triggered location. WHY: Moving Renown from a location to the same location is a no-op, so no point offering that choice.

**Pressure:** Uses `USSURAN_INTRIGUE_PRESSURE_TYPE` flag to get tie-wins behavior. Pressures at the chosen performer's location with Influence.

**On success:** Removes 1 Renown from the triggered location and adds 1 to the performer's location (marked as a move via `isMove = true`).

**"Even during Planning":** No special code needed. The event system fires `EventReknownAddedToLocation` regardless of phase, and the reaction checks `LOCATION_HAND` which is valid during planning too. The card text notation is just a player-facing clarification.

**Potential concern:** The `createReknownAddedToLocationEvent` with `isMove = true` in the success handler could re-trigger this same reaction if it fires again. However, `setUsed()` is called before the events are queued, so `isAvailable()` should return false and prevent infinite loops.
