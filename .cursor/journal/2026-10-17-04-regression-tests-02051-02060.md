## WHYs pinned
- **02051**: Unengaged Sorcerer in the city plus another engaged character there. Home sorcerers do not count. Availability uses `getCharactersAtLocation`, so an uncontrolled engaged neighbor does not open the action. `isValidTarget` does not repeat that filter — the click still accepts them. Friendly engaged characters are legal targets. Confirm order: sorcery start, engage performer, en garde target, locker, sorcery played, action resolved. Bare `nextState()` (sole empty transition).
- **02052**: Resolve adds 1 Renown to the Bazaar (not a move) then medium-priority transition `02052`. Args are location *names* with Renown, excluding the Bazaar. Move shares one batch and the add is `isMove`. Unknown location throws `\Exception` from `getCityLocation` before the card's null check (that null check is dead). Pass uses bare `nextState()`; a successful move uses `nextState("")`. Both match the sole empty transition. Forced: scheme must be Home, `IN_DUEL`, and the **challenger's** location is the duel location (defender's location is ignored). Collector is the surviving participant's controller. Empty Bazaar, a non-participant, or a scheme that left Home does nothing.
- **02053**: Resolve only adds Docks Renown. Home-move `eventCheck` consumes `UNDER_COVER_OF_THE_NIGHT` and throws. Dusk phase end clears `ProcessedPiles`. Pile order is players then city; empty piles are skipped. City discard is `moveCard`'d to the City Locker immediately and does **not** queue `EventCardSentToLocker`. A player discard only queues remove + locker and leaves `Location` alone. Pass marks the current pile processed. Unknown performer id on the reaction still `setUsed` and does not add the condition. Engaged city characters are still buttons. Home characters are not.
- **02054 maneuver**: Availability does **not** read Location. "From your dueling line" is not enforced; a pistol in hand is available in a duel if `canAttachTo` passes. `createAttachmentEquippedEvent` returns `EventAttachmentEquipping`. Discount is the printed Wealth, cost is 0, `asAction` false. Draw when `ModifiedCombat <= 1` (1 still draws).
- **Technique_02054**: Implements `IRangedAbility`. Resolve transition player is the adversary controller. Parry +1 only while `AdversarySufferedWound` is false. Choosing the wound (id 1) writes the card immediately via `updateCardObjectInDb` because `nextState` rebuilds before IsUpdated flushes. Decline (id 2) does not write. Wound target is `getDuelOpponentId(actor id)` — the stub returns `duelOpponent`, not the actor. Cancel, new round, and duel end clear the flag.
- **02055**: Copy list ignores source availability. Skips `ClassId === Technique_02055` (any Dame technique, not just this instance) and `IsTemporaryCopy`. Args ignore the active player; they follow the duel actor. Confirm does **not** re-check copyable — passing Dame's own id still clones it. Activate `ownerId` is the Dame card, not the actor. Sink `playerId` is `OwnerId`; unequip uses `ControllerId`. `onTop` false. `Used` is cleared only when a host exists (faction deck never sees DuelEnd). Unattached act still copies, leaves Used, and does not sink. Re-equip of a Used Dame clears Used because `isAvailable()` short-circuits before `isAvailableToPlayer`. Transition name is `cardChosen` (the only transition; not empty).
- **02056**: `canAttachTo` and `EventAttachmentEquipping` both require Duelist. A different attachment id does not throw. Technique: `ModifiedFinesse >= 3` is Riposte, otherwise Parry. Unattached (`getOwningCharacter` null) changes nothing. The finesse check is on the host, not the actor global.
- **02057**: Availability/args omit participants and uncontrolled characters. `isValidTarget` accepts an uncontrolled bystander. Brute wounds twice. `nextState()` is inside the state if.
- **02058**: Does not call `interventionCheck` (that would reject an adjacent character who is about to be engaged). Home is adjacent to every city location (`includeHome` default). Adjacency reads `PLAYER_COUNT` global, not `$game->playerCount`. Ole's Inn joins the Docks only above 2. Valeri / Torvo / Raven: no offer. Legendary: Leader. Sworn-path covered via the Duelist who fails Legendary. Aja (and the same gate for Celerity): `ModifiedFinesse >= 3`. Pay does not set Used. Discount is +1 for Hero or Knight, only in hand, only after PerformerId is latched. Trigger swaps `DUEL_DEFENDER` and `CHOSEN_TARGET` immediately, sets `CHALLENGE_ACCEPTED`, queues engage then a move with `engage=false`. Turn end clears the latch (discount drops, buttons collapse to Pass).
- **02059 reaction**: Holds the wound when `abilityId` is non-empty and the ability owner's controller differs — including controller 0. Card-level fallback (`getAbilityById` miss) uses source `ControllerId`, and 0 is not an opponent. A second wound while one is saved is not canceled. Ignore pays and leaves the original canceled. Decline re-emits the pre-cancel clone and sets `skipNextEvent` so that re-emit does not re-offer. The wound after that offers again. `savedWoundEvent === null` is why Used cannot be the only guard before pay.
- **Maneuver_02059**: Finesse `>= 3` is availability only. Calc adds +1 Riposte whenever the maneuver id matches, even if finesse later dropped.
- **02060a**: Offer when the challenger character's controller owns the risk in hand. Pass does not clear `ChallengerId` / `TargetId`. Turn end does. Pay wounds challenger then the refusing target.
- **02060b**: Offer keys off `challengingPlayerId` / `defendingPlayerId`, not the character controllers. Either participant null or `characterIsInDiscardOrLocker` suppresses the offer. At pay time, the adversary wound is skipped if they are no longer at the participant's location; your wound still happens. Pass keeps the latch. Turn end clears it.
