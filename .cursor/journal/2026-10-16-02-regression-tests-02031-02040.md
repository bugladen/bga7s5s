## WHYs pinned
- **02031/02032**: muster/approach creates Damned in `Locker-{controller}` + SentToLocker. Destroy musters Damned back to Doomed's location only if a `_02032` is already in that locker. Dawn destroys Damned (`reason` Dawn Phase). `canEnterApproachDeck` false. Reaction offers only on Damned's own muster when a Risk is in the locker; pass does not set Used.
- **02033 action**: adjacent *uncontrolled* `ICityDeckCard` only. Move `engage=false`. Revelry combat card queues Lethal via `EventThreatModified` (defender lethal when Rosa is the challenger).
- **Reaction_02033**: one offer per non-empty `abilityId` until `EventActionResolved`, even after pass clears pending (Blood Mark). Empty abilityId does not stick. Dusk clears pending/awaiting/consumed. Wrong-player discard click does not clear awaiting. Uncontrolled CityCharacter skipped.
- **Action_02034**: `ModifiedCombat >= 2`, engaged targets still legal. Decline (id 2) draws for Torvo. Accept (id 1) sets performer=target, target=Torvo, `STAT_COMBAT`, `TORVO_ESPADA_CHALLENGE_TYPE` 15. Both response paths `nextState('')`.
- **Technique_02034**: duel-only. +1 Parry, or +1 Riposte if Aldana is in *Torvo's* dueling line (controller filter on `getCardObjectsAtLocation`).
- **02035**: resolve chooser only if some city location has 0 Renown; required count is `min(2, empty)`. Action: opposed Scoundrel, location Renown > 0, Finesse pressure, Caper flag OR'd onto PRESSURE_TYPE. Success removes 1 + gains 1. Failure and zero-renown success still ActionResolved.
- **02036**: resolve +2 Renown on City Docks. 02036a: non-Pirate at performer location; discard avoids move; pass moves Home `engage=false`. 02036b: Pirate not already at docks whose location lists docks as adjacent.
- **Adjacency asymmetry**: Docks list Ole's Inn only at 3+ players, but Ole's Inn *always* lists the docks. 02036b asks from the Pirate's location, so Ole's Inn is legal at 2 players. Do not "fix" that test to require 3 players.
- **02037 Forced**: discard from hand or play sets `canceled` and queues `EventCardAddedToFactionDeck` with `onTop=false`.
- **Reaction_02037**: must already be attached; opposing challenger; another friendly character at that location (not the current host). Equip queues **`EventAttachmentEquipping`** — `createAttachmentEquippedEvent` is a misleading name. Pass does not set Used. Invalid target throws after clearing pending.
- **Technique_02037**: Resolve arms from `adversaryId` else `CHOSEN_TARGET`, `AwaitingAdversaryRound=true`. Owner NewRound while awaiting does NOT clear (01186/01193). Adversary NewRound clears awaiting and the gamble block becomes live. Owner NewRound after that, DuelEnd, TechniqueCanceled, and ChallengeRejected *by the owning character* clear. Gamble throws only when armed, not awaiting, and actor is the blocked adversary.
- **02038**: one class, two ids (`Maneuver_02038_Pirate` / `_Duelist`). Trait + strictly greater Combat or Finesse. Resolve offers the adversary. id 1 wound, id 2 draw for the risk owner.
- **02039 reaction**: opponent `EventCombatCardAnnounced`, in hand, `IN_DUEL`. addThreat → pay state `PAY_STATE_IN_HAND_REACTION` (Used only on `EventRiskReactionTriggered`, which queues threat 1/1).
- **Maneuver_02039**: Resolve sets `IsActive`. EndOfRound banks `PENDING_CHALLENGER_THREAT` and `PENDING_DEFENDER_THREAT` +1 for the *next* round, then clears. Cancel before end of round spends nothing.
- **02040**: move Home `engage=true`, heal 1 only if `Wounds > 0`, then ActionResolved.
