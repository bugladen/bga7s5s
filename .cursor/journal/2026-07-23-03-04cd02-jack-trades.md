# _04cd02 Jack Trades (bas City Character)

## Card Text
- Negotiable (property)
- Passive: While you control a Diplomat, Duelist, Pirate, or Zealot at Jack's location, he gains that trait.

## Classification
1. Negotiable → `$this->Negotiable = true` (already stubbed)
2. Continuous location-scoped trait copy → Angeline `_03026` pattern (handleEvent recompute), not Forced/Action/Reaction

## WHY choices
- Mirror Angeline `_03026` event set (CardMoved / Mustered / Recruited / Destroyed) rather than invent — same "while you control X at my location" shape.
- Track `$CopiedTraits` for grants from THIS ability only. WHY: naive `removeTrait` when the ally leaves would also strip the same trait if an attachment had granted it (Guild Triskelion → Duelist, Cross of Martyrs → Zealot).
- Exclude Jack himself from the source scan. WHY: once he gains Diplomat he'd permanently latch it by counting himself.
- Exclude `$event->characterId` on EventCharacterDestroyed. WHY: that event runs card handlers BEFORE the hub moves the destroyed character to the locker (runEventHubAfterCards=true), so without exclusion the dying ally still counts and the trait never drops. Angeline has this latent bug; fixed here deliberately.
- Stale EventCardMoved location handling copied from Angeline (exclude mover-out, peek mover-in).
- Did NOT hook EventAttachmentEquipped. WHY: attachment trait-grants happen in the attachment's own handleEvent during the same pass — ordering vs Jack is nondeterministic, and Angeline skips this edge case too. Printed-trait allies cover the intended play pattern. Documented as known gap.
- Combat stub was 1; printed card is 2/2/2. WealthCost was missing; printed cost is 2. Fixed both from the card image.
- Factotum already in TraitNames — no Traits.php edit.
