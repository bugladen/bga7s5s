# Sorte Deck (01181) Audit

## Card Text
> Traits: Sorte, Trinket
> **Reaction:** After a character at this location is wounded, engage this card • Heal a wound from them, or two instead if the equipped character is a Strega.

## Two bugs found and fixed

### Bug 1: Missing `!$event->canceled` guard in handleEvent

Both comparable wound-intercepting reactions (`Reaction_01014` Vittoria and `Reaction_01032` Unyielding Loyalty) check `!$event->canceled` before processing `EventCharacterBeingWounded`. Sorte Deck did not. This meant if another reaction already canceled a wound event (e.g., Vittoria intercepting first), Sorte Deck would still try to intercept the same event — cloning an already-canceled event and storing a second copy. When both reactions release their stored events, things go wrong: Sorte Deck's clone still has `canceled = true` so the hub skips it, but Sorte Deck already set `WoundsHealedIncoming` and queued a heal event that has no matching wound.

WHY the guard matters: Cards process events in `Theah::runEvents` iteration order over `$this->cards`. Without the guard, behavior depends on which card appears first in the array — fragile and inconsistent. With it, whichever reaction cancels first "owns" the event and subsequent reactions correctly skip it.

**Fix**: Added `!$event->canceled` to the condition at line 56.

### Bug 2: Off-by-one in wound count check for "Heal 2 Wounds" button

The check `$character->Wounds > 1` was used to decide whether to show "Heal 2 Wounds" when the equipped character is a Strega. Problem: at the time this check runs, the incoming wound has been intercepted (event canceled) and hasn't been applied yet. So `$character->Wounds` is the count *before* the incoming wound.

Example: character has 1 wound, receives 1 more → total after wound = 2 → healing 2 is meaningful. But `1 > 1` = false → "Heal 2" button hidden.

WHY the stored event matters for the fix: When `characterWoundedEvent` is non-null (first target, wound intercepted), the wound hasn't applied, so we add `characterWoundedEvent->wounds` to get the effective total. When null (subsequent targets after a pass, wound already applied through the hub), `$character->Wounds` already includes the wound and the simple check is correct.

**Fix**: Changed to `$effectiveWounds = $character->Wounds + ($this->characterWoundedEvent !== null ? $this->characterWoundedEvent->wounds : 0)` and check `$effectiveWounds > 1`.

## What checks out

- **Trigger**: Listens for `EventCharacterBeingWounded` + location match + not engaged ✓
- **Event interception**: Cancels the first BeingWounded event, clones it, re-queues later via `releaseEvent` ✓
- **`skipNextEvent`**: Prevents re-triggering when the released clone re-enters the event loop ✓
- **Engage cost**: `createCardEngagedEvent` fires on heal ✓
- **Strega check**: `getOwningCharacter` correctly traverses attachment → attached character ✓
- **`WoundsHealedIncoming`**: Set before wound re-queues so `Character::handleEvent` lethal check sees it ✓
- **Multi-wound cleanup**: `deleteTransitionEvents` removes queued transitions when heal is chosen; `HealTargetIds` cleared ✓
- **Pass flow**: Shifts first target, releases stored event, sets `skipNextEvent`, doesn't engage card — correctly allows future reactions ✓
- **Dusk reset**: Inherited from `CardReaction::handleEvent` which resets `Used` on `EventDuskEndOfDay` ✓
- **Card properties**: CityAttachment, CityCardNumber 5, WealthCost 1, traits Sorte/Trinket all match ✓
