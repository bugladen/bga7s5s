# Takama Siad (_01199) Audit

## Card Text
> Negotiable (You may parley when paying for this card.)
> **Reaction:** After a duel, if your character that participated is at Takama's location • Heal a wound from them.

## What Checked Out
- Negotiable flag set correctly
- Trigger on `EventDuelEnd` correct
- Location check correct (`challenger->Location == takama->Location`)
- Ownership check correct (`ControllerId` match)
- Heals exactly 1 wound via `createCharacterBeingHealedEvent(..., 1, ...)`
- `Used` flag properly resets at dusk via parent `CardReaction::handleEvent`
- Target ID resets at dusk in own handler
- Self-healing works: if Takama herself duels, she's at her own location

## Bug Fixed: Both-Valid-Targets Edge Case

**Problem:** The `handleEvent` used `if`/`else if` when checking challenger vs defender. If both duelists are controlled by the same player, both are at Takama's location, and both have wounds, only the challenger was ever offered for healing. The defender was silently skipped.

**WHY this matters:** The card says "your character that participated" — if both participants are yours, you should choose which to heal.

**Fix:** Adopted the `Reaction_01037` pattern:
- Replaced single `$TargetCharacterId` with `$ChallengerId` and `$DefenderId`
- Changed `if`/`else if` to two independent `if` blocks, capturing each valid target
- Queue one reaction transition if at least one valid target exists
- `getReactionButtonProperties` shows a named button per valid target ("Heal {CharacterName}")
- `performReaction` parses the character ID from the reactionId (`healWound-{id}`)

**WHY this approach over alternatives:**
- Matches the existing pattern from `Reaction_01037` which also stores both duel participant IDs and gives per-target buttons
- Using two named fields (`ChallengerId`/`DefenderId`) instead of an array keeps serialization consistent with other reactions
- Always using `healWound-{id}` format (even with one target) keeps the code path uniform and avoids branching
