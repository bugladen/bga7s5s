# Torres Cloak (_03044) — create-faction-attachment

## Card text
1. Offhand (already `$this->OffHand = true`)
2. May only equip to your Duelist
3. Reaction: When equipped participant's adversary would resolve a Maneuver or Technique, engage this card • Cancel the effects unless they discard a card.

## Context
Continuing FAF Castille after El Gato's Mask (_03043).

## Approach / WHY

### Equip restriction
Mirror Main Gauche `_02056` / Cavalier Hat `_01073`: dual-gate `eventCheck(EventAttachmentEquipping)` + `canAttachTo` for Duelist. Use `\Bga\GameFramework\UserException` (not deprecated BgaUserException).

### Reaction — cancel unless discard
Compose:
- **Trigger/cancel mechanics:** `Reaction_01047` (Kaspar Panzerhand — attachment Technique cancel) + `Reaction_01146b` (scheme Maneuver OR Technique cancel). Listen `EventTechniqueActivated` / `EventManeuverActivated`, `IN_DUEL`, HIGH_PRIORITY reaction transition, `deleteTechniqueEvents`/`deleteManeuverEvents` + Canceled event.
- **Engage cost + multi-stage cross-player:** `Reaction_03007` (Matushka — engage then opponent faces "unless") + `Reaction_02033` (hand-card discard buttons via `discardHand-{id}`).

### Timing: Activated not Resolve
"Would resolve" = interrupt before effects. All existing cancel reactions fire on `*Activated`, then delete queued resolve events. Do NOT wait for `EventResolve*`.

### Adversary gate (fix 01047's ID compare)
`Reaction_01047` compares `owningCharacter->ControllerId == getDuelOpponentId(actor)` and `actor->Id == event->playerId` — those mix player ids with character ids and look broken. Correct reading of printed text:
- Equipped character IS the duel adversary of the round actor
- Activating player IS the actor's controller

```
owningCharacter->Id == getDuelOpponentId(actor->Id)
event->playerId == actor->ControllerId
```

### Stages
- `offer` (cloak controller): Engage / Pass. Engage → queue engage event, setUsed, then either auto-cancel (empty hand + log) or `threat` to adversary.
- `threat` (adversary): discardHand-{id} keeps effects; `acceptCancel` cancels like 01146b.
WHY multi-stage reaction transitions (not a duel sub-state): reactions can fire from any duel interrupt window; dedicated states only work from one events table. Same WHY as 03007.

### HIGH_PRIORITY on both transitions
01047/01146b set HIGH_PRIORITY (2) so the offer runs before MEDIUM resolve events. Second transition to adversary must ALSO be HIGH_PRIORITY or resolve fires while adversary is still deciding.

### setUsed on engage (not only on successful cancel)
Engage is the printed cost of attempting the cancel. Adversary paying discard still consumed the reaction for the day.

## Bugfix: Technique_01093 not canceled (2026-07-13)

**Symptom:** Engaged Torres Cloak vs Maya Technique_01093; technique still resolved (-1 Riposte / discard).

**Root cause:** `setUsed(true)` on Engage. `Theah::runEvents` skips reaction transitions when `!$reaction->isAvailable()` (prevents duplicate offers). Threat-stage transition was dropped; MEDIUM `EventResolveTechnique` + `EventDuelCalculateTechniqueValues` ran normally.

**Fix:** Defer `setUsed` to `finalizeAfterEngage` (empty-hand cancel / discard / acceptCancel) — same as Reaction_03007. Engage cost stays via `createCardEngagedEvent`; Used is once-per-day after the flow completes.

**WHY this bit Technique_01093 specifically:** empty-hand path cancels in the same `performReaction` (no second transition), so it would have worked. Maya adversary usually has cards → threat transition required → bug.

## Bugfix 2: cloak player still reaches duelChooseTechnique_01093 (2026-07-13)

**Symptom:** After setUsed fix, Maya gets Torres Cloak threat (discard / Accept Cancel), but cloak player still enters `duelChooseTechnique_01093`.

**Root cause / redesign:** Cancel-later left `EventResolveTechnique` + `EventDuelCalculateTechniqueValues` in the queue during the whole threat wait. If Accept Cancel failed to strip them (empty TechniqueId after serialize, etc.), 01093 transition queued from Resolve. Even on a clean Accept Cancel path, cancel-later is fragile for multi-stage.

**Fix — cancel-first on Engage:**
1. Engage → `deleteTechniqueEvents` / clear CHOSEN_* immediately (do NOT fire *Canceled yet)
2. Accept Cancel / empty hand → fire `TechniqueCanceled`/`ManeuverCanceled`, finalize
3. Discard to keep → re-queue Resolve + Calculate (+ restore CHOSEN_*), finalize

Also made stage/TechniqueId/context fields `public` like 01047/01146b for safer nested serialize.

**Rules note:** If Maya *discards to keep*, cloak getting `duelChooseTechnique_01093` is correct — the technique was not canceled. Accept Cancel must stop it.
