# Eko Sorridi (01182) Audit

## Card Text
> Negotiable (You may parley when paying for this card.)
> **City Reaction:** Before an opposing character moves from this location • Wound them. (Even during Dusk.)

## Verdict: No Bugs

### Negotiable
- `$this->Negotiable = true;` in the constructor. ✓

### City Reaction trigger — "Before an opposing character moves from this location"
- Listens for `EventCardMoved`. Checks:
  - `$this->isAvailable()` — not already used this day. ✓
  - `$ekko->isControlled()` — Eko must be controlled. ✓
  - `$card instanceof Character` — only Characters trigger it. ✓
  - `$event->theah->cardInCity($ekko)` — Eko must be in the city (City Reaction requirement). ✓
  - `$ekko->ControllerId != $card->ControllerId` — "opposing" check. ✓
  - `$ekko->Location == $event->fromLocation` — character is leaving FROM Eko's location. ✓

#### "Before" timing analysis
The card says "Before" but uses `EventCardMoved` (committed move). Investigated whether this should be `EventCardMoving` (the pre-commit/cancellable event, used by _01140 Stubborn).

**Conclusion: EventCardMoved is correct for this card.**

WHY: The event queue is priority-ordered (DB `ORDER BY event_priority`). Reaction transitions have `REACTION_PRIORITY = 6`, while `EventCardMoved` defaults to `MEDIUM_PRIORITY = 3`. Lower number = processed first. So even if Eko listened to `EventCardMoving`, the hub would queue `EventCardMoved` (priority 3) which would process BEFORE the reaction transition (priority 6). The wound would still resolve after the move.

Stubborn (_01140) can achieve true "Before" timing because it:
1. Cancels the movement immediately in `handleEvent` (sets `$event->canceled = true` inline, before the hub runs)
2. Uses `stackEvent` (which forces lowest priority number) instead of `queueEvent`
3. If player declines, re-queues the original `EventCardMoving`

This cancel-and-re-queue pattern is fundamentally different from Eko's wound. Eko can't cancel the movement and re-queue — wounding is a separate effect, not a replacement for the move. The "Before" in Eko's card text describes the trigger condition ("when a character is about to leave") rather than strict timing the engine needs to enforce.

All non-cancel movement reactions in the codebase (_01137, _01066, _01173, _01196) use `EventCardMoved`. Consistent.

### Effect — "Wound them"
- `createCharacterBeingWoundedEvent($this->TargetCharacterId, $ekko->Id, 1, ...)` — wounds 1. "Wound them" = 1 wound. ✓
- Source is Eko's Id, ability is the reaction's Id. ✓
- `setUsed(true)` after wounding. ✓
- Pass does NOT set Used — correct, player can decline one character and wound a later one. Same pattern as Stubborn's decline. ✓

### "Even during Dusk"
- No special code needed. `isAvailable()` (from `CardAbilityTrait`) only checks `$this->Used == false`. No phase gating exists in the reaction framework. Movement events fire normally during Dusk. The "(Even during Dusk)" reminder in the card text is handled inherently. ✓
- Confirmed by checking all three "Even during Dusk" cards (_01140, _01179, _01182) — none have Dusk-specific code.
