# Iron Reply (_01054) Audit

## Card Text
> While your participant is equipped with an Eisenfaust attachment, this card has -1 cost.
> Maneuver: If your participant has equal or greater [Com] than the adversary, or is equipped with an Eisenfaust attachment • Wound the adversary.

## Bug 1 (Critical): isAvailableToPlayer used AND instead of OR

The card text specifies two conditions joined by OR:
- Participant has >= [Com] than adversary
- Participant is equipped with an Eisenfaust attachment

Old code checked combat first and returned `false` if adversary had more combat — blocking the Eisenfaust path entirely. Then after passing the combat check, it ONLY returned `true` if Eisenfaust was found, meaning equal/greater combat alone wasn't sufficient either. Effectively AND logic.

Fixed to: if combat >= adversary → true (return early). Otherwise, check for Eisenfaust. Both paths independently allow the maneuver.

## Bug 2 (Minor): Cost discount stacked per Eisenfaust attachment

The `foreach` over attachments added +1 discount for every Eisenfaust attachment found. Card text says "this card has -1 cost" — a flat boolean condition. Added `break` after finding the first Eisenfaust. In practice this likely never triggered because the only Eisenfaust attachment (_01047 Kaspar's Panzerhand) has Unique, but the code should match the card text.

Also tweaked the explanation string from "reduces the cost of Maneuver by 1" to "reduces the cost by 1" to better match card text (the -1 applies to the card, not specifically the maneuver).

## handleEvent — Wound Adversary

Verified correct: on `EventResolveManeuver`, creates a wound event targeting the adversary for 1 wound. Matches card text.
