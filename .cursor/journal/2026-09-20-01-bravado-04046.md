# Bravado (_04046) — Duelist Reaction + Maneuver

## Card
Ussura Risk. Wealth 0. 1/1/2.
- **Duelist Reaction:** At the end of your adversary's round • Add a threat to your Duelist participant. Italic reminder: duel ends only if no threat in any pool.
- **Duelist Maneuver:** +1 Parry.

## Classification
- Reaction → Pattern D.2 (single-stage pay → effect on `EventRiskReactionTriggered`)

- No Cesca (no printed Target / character chooser)
- No custom states / JS — `DUEL_END_OF_ROUND_EVENTS` already wires reaction + pay

## WHY pending threat, not createThreatModifiedEvent
Same trap as Raise the Stakes `_02039` (journal 2026-04-06-04): EventDuelEndOfRound fires *after* Resolve Threat. Mutating ending_* via ThreatModified rewrites the finished round UI and can bump wounds_taken. Use `PENDING_CHALLENGER_THREAT` / `PENDING_DEFENDER_THREAT` so:
1. stDuelNextPlayer sees pending and does not end the duel (italic reminder)
2. stDuelNewRound applies it as next-round starting threat

Map "your participant" → challenger or defender id, bump only that side's pending global (not both like 02039).

## Reaction gates
- Hand (`Location == LOCATION_HAND`)
- IN_DUEL
- `$event->playerId != owner->ControllerId` (adversary's round)
- Your participant (duel opponent of actor) has Duelist + not discard/locker
- Stash `$participantId` before pay (Pattern D.2)
