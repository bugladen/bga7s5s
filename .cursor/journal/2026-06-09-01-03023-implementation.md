# 03023 Second Wind - Implementation Notes

## Card Text
- **City Action:** If your performer has two or more wounds • They heal a wound.
- **Gambling Maneuver:** Your participant's threat is not converted to wounds this round unless your adversary is absent. (The threat remains for your next round.)

## Implementation Details

### Pattern A - City Action (Action_03023)
Simple `RiskCityAction` that:
1. Sets `RequiresPerformerSelected = true` because we need to know who to heal
2. Filters performers to those with 2+ wounds in `getPerformersForAction`
3. On `EventActionTriggered`, queues:
   - `createCharacterBeingHealedEvent` (1 wound)
   - `createActionResolvedEvent`
4. NO sub-state needed - resolves inline in handleEvent

### Pattern C - Gambling Maneuver (Maneuver_03023)
Implements threat conversion suppression:

**Key Discovery:** The game applies threat-to-wounds at END of ROUND in `stDuelEndOfRound()`:
- Line 1456-1494: If threat > 0, queues `createCharacterBeingWoundedEvent`
- This is NOT automatic at end of each maneuver, only at end of round

**Implementation Strategy:**
1. On `EventResolveManeuver`: Store the actor ID
2. On `EventCharacterBeingWounded`: Check if:
   - This wound is being applied to the actor (the participant)
   - This maneuver was active (ActorId != 0)
   - The adversary is NOT absent (not in discard/locker)
3. If all true, suppress wound by setting `event->wounds = 0`
4. Clean up state tracking on `EventManeuverCanceled` and `EventDuelEndOfRound`

**Why this works:**
- The maneuver only suppresses wounds if adversary is PRESENT
- If adversary is absent, wound is applied normally (as per card text)
- Threat DOESN'T get suppressed, only the wound conversion
- Threat carries forward naturally via ending_*_threat fields

### Wiring Notes
- No new states needed (inline resolution)
- No state.inc.php changes needed
- No new GameState classes needed
- Action filters to performers with 2+ wounds automatically
- Maneuver gates on `DUEL_GAMBLED` (Gambling Maneuver)

### Why Not Other Approaches?
- Could not directly modify `wounds_taken` in DB because it's calculated in DB.php, not in maneuver
- Could not gate on EventDuelNewRound because wounds are already in the event
- Direct event suppression (EventCharacterBeingWounded) is cleanest and most maintainable
