## Decisions / WHY

### Action_01160 args
One-line `cardInCity` filter in `getArgsFromAction` — matches `isAvailable` / `isValidTarget` / act. UI was listing Home wounded non-Leaders that act refuses. Clear bug, not design.

### Maneuver_01164 EndOfRound owner dirty
Cancel path already `$owner->IsUpdated = true`. EOR cleared `MoveCharacter`/`MoveLocation` on the Maneuver (serialized on the Risk) but only dirtied `$character`. Without owner flush, DB can keep the armed deferred move. Fix: dirty owner when clearing, same as cancel. Keep `$character->IsUpdated` (harmless; was already there).

### Action_01167 → RiskCityAction
Card text is **City Action**. Robbery (`Action_01113`) uses `RiskCityAction` for the same shape. 01167 already gates performers via `getCharactersInCityByPlayerId`; base-class change makes hierarchy match print and gets the city-character availability check from parent. Does **not** add `RequiresPerformerSelected` — Liberating Goods picks performer in step 3 after opponent/attachment, unlike Robbery.

### Action_01171 opposing re-check
`isValidTargetForAbility` only checked same-location + Mercenary. Args filtered opposing; client bypass could engage/Home your own Merc. Add `isNotControlledByPlayer` check to match args / printed "opposing".

### Action_01172 Torsten cancel
Current order: wound → Start → move → … Wound processes before Torsten can stack on Start, so cancel cannot un-wound. Leontine (`Action_01068`) / Ravenna (`Action_01201`) do Start **before** wound.

Also stamp a shared `batchId` on Start/wound/move/ActionResolved/Played. WHY: Torsten cancel uses `deleteEventBatch`; performer wound does not target Torsten so `deleteEventsTargetingCard` alone leaves it. Without batchId, reorder alone still leaves the wound queued after cancel. Played stays after ActionResolved (Cesca journal 2026-09-01-01).
