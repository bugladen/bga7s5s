## Classification

- Engage this card cost on EventResolveTechnique (mirror Technique_01049)
- Remainder-of-duel effects via **condition** on the adversary (Eddie request)

## WHY condition for restrictions
Soline (_01089) already uses a Finesse condition for tooltip + cleanup. Indomitable Will uses a condition as the source of truth for lasting state. Putting -1 Finesse / cannot-swap / cannot-move behind one `HARPOON_CONDITION` means:
1. Tooltip shows the restriction string for free (conditions list)
2. Move/swap gates check `hasCondition` — works even if we forget a Technique flag
3. Clear on DuelEnd / TechniqueCanceled restores Finesse + removes condition (Soline raise/lower shape)

## Enforcement (shipped)
- **Apply:** Technique on EventResolveTechnique — engage attachment, Finesse-1 event, addCondition, notify started
- **Move:** `Character::eventCheck` on EventCardMoving when character has condition (skip unstoppable). WHY Character not Technique: condition is the source of truth even if Harpoon somehow leaves `$theah->cards` mid-duel.
- **Swap:** Gate in `Theah::swapParticipantsInDuel` BEFORE DB mutate — ChallengerSwapped/DefenderSwapped fire after swap. Check `oldParticipant->hasCondition(HARPOON_CONDITION)`.
- **Clear:** EventDuelEnd + EventTechniqueCanceled — raise Finesse, removeCondition, notify ended

## Alternatives considered
- Technique-only eventCheck for swap on ChallengerSwapped: too late (DB already mutated)
- Technique flag `$Active` instead of condition: Eddie asked for condition; also worse for tooltip / orphaned state
- Blocking intervene: text says "swapped" not intervene; intervene is challenge-time, technique is mid-duel only

## Maneuver_01033 line endings (follow-up)
