# Valeri Mikhailov (01123) Audit

## Card Overview
Valeri Mikhailov, "Champion Narcissist" — Ussura faction character. Resolve 4, Combat 2, Finesse 3, Influence 1. Traits: Duelist, Ussura.

Two abilities:
- **Action:** Engage Valeri and target an enemy character at an adjacent City location. Move Valeri there and issue them a [Combat] challenge. Other characters cannot intervene.
- **Technique:** +1 Thrust. If Valeri has fewer wounds than the adversary, +1 Riposte instead.

## Action (Action_01123) — Correct
- Extends `CharacterAction`, implements `IAbilityThatTargetsCharacters`
- Availability check: Valeri must not be engaged, must have enemy characters at adjacent city locations
- On use: moves Valeri to target's location (with engage=true via `createCardMovingEvent`), sets up a Combat challenge (`STAT_COMBAT`), sets `VALERI_MIKHAILOV_CHALLENGE_TYPE` which blocks all intervention in `FrameworkActionsTrait`
- Transitions to `HIGH_DRAMA_CHALLENGE_ACTION_TECHNIQUE_AVAILABLE` via "01123_2" for standard challenge flow
- Pre-commit checks pass: has `createActionResolvedEvent()` and `$this->setUsed()`

## Technique (Technique_01123) — BUG FOUND AND FIXED

### The Bug
The wound comparison used `getDuelRoundActor()` and `getDuelRoundOpponent()` instead of `$event->actorId` and `$event->adversaryId`. The "round actor" is whoever is currently attacking in the duel round, which alternates. The card text says "If **Valeri** has fewer wounds" — the check must always compare Valeri's wounds, not the current round attacker's.

WHY this matters: In rounds where the opponent is the attacker, `getDuelRoundActor()` returns the opponent, flipping the wound comparison and potentially granting the wrong bonus (Thrust when Riposte was deserved, or vice versa).

### The Fix
Changed from:
```php
$actor = $event->theah->getDuelRoundActor();
$adversary = $event->theah->getDuelRoundOpponent();
```
To:
```php
$valeri = $event->theah->getCharacterById($event->actorId);
$adversary = $event->theah->getCharacterById($event->adversaryId);
```

`$event->actorId` is set to the technique owner's character ID when `createDuelCalculateTechniqueValuesEvent` is called in `FrameworkActionsTrait`, so this always refers to Valeri.

### EventGenerateChallengeThreat
The technique also adds +1 to `adversaryThreat` unconditionally. This matches the pattern from Technique_01067 (another Thrust/Riposte technique). Threat is always +1 regardless of whether Thrust or Riposte is granted — both are offensive combat values.
