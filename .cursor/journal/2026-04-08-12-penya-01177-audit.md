# Penya Shows The Way (01177) Audit

## Card Text
> Traits: Heroic, Savvy
> **Reaction:** At the beginning of Dusk, if you control this location • You may choose one of your characters here. If you do, the chosen character does not move Home during Dusk and you look at the top three cards of the City Deck. Replace them in any order.

## Verdict: No Bugs Found

### Event flow for "does not move Home"

The prevent-move mechanism uses `eventCheck` on `EventCardMoved` (not `EventCardMoving`). Initially thought this was a bug, but traced the full chain:

1. `stDuskPhaseCleanup` queues `EventCardMoving` via `queueEvent` → `eventCheck` runs on `EventCardMoving` → `_01177::eventCheck` checks for `EventCardMoved` → doesn't match → event IS queued
2. `runEvents` processes `EventCardMoving` → EventHub handler creates `EventCardMoved` → `queueEvent` → `eventCheck` catches it → removes `HELPED_BY_PENYA` condition → throws `BgaUserException` → `EventCardMoved` NOT queued → actual move never happens

WHY this works despite the exception: `queueEvent` catches the exception. The condition removal is in-memory (`IsUpdated = true`). After the EventHub processes `EventCardMoving`, `runEvents` iterates all cards and persists any with `IsUpdated = true`. So the condition removal is saved.

This approach differs from Stubborn (01140), which sets `event->canceled = true` on `EventCardMoving`. Penya lets `EventCardMoving` process but blocks `EventCardMoved`. Practical difference: other cards' `handleEvent` for `EventCardMoving` still fires, but the physical move doesn't happen. Not a problem for this card's use case.

### Reorder logic

JS `onCardsSorted` sorts by descending `order` attribute before sending to PHP. PHP iterates the array and calls `insertCardOnExtremePosition(id, CITY_DECK, true)` for each. Since each insert goes to the top, the last card processed ends up on top. With descending sort, the lowest-order card (position 1 = top) is last in the array, so it ends up on top. Correct.

### Everything else verified
- **"may choose"**: `actPassWithPass` in state definition allows declining ✓
- **"if you control this location"**: `$location->Controller != 0` then filters characters by controller ✓ (City Event Card — "you" = whoever controls the location)
- **"your characters here"**: `getCharactersAtLocation` + `ControllerId == $location->Controller` ✓
- **Private args**: Second state uses `argsForStatePrivate` so opponents can't see top 3 cards ✓
- **City deck edge case**: `getCardsOnTopOfCityDeck` shuffles discard back if deck < requested ✓
- **Zombie handling**: Both states pass → safe default ✓
- **UI cleanup**: `OnLeavingState` clears selectable cards and choose list, resets sort order ✓
- **Condition cleanup**: Removed in `eventCheck` before throwing, persisted via `IsUpdated` in next `runEvents` cycle ✓

### Minor style note (not a bug)
`actFromCardWithId` adds condition directly via `$selectedCharacter->Conditions[] = Game::HELPED_BY_PENYA` instead of `$selectedCharacter->addCondition(...)`. No functional impact since `updateCardObjectInDb` is called immediately after.
