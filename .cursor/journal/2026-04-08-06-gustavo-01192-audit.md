# Gustavo (01192) Audit

## Card Text
> Negotiable (You may parley when paying for this card.)
> **City Action:** Reveal cards from your deck equal to Gustavo's [Influence]. Put a revealed risk into your hand. Sink the rest.

## Bug Found: Missing sink in actFromActionPass

When the player passes (either no Risks among the revealed cards, or choosing not to take one), the revealed cards were left sitting on top of the deck. The card text says "Sink the rest" which should apply even when no Risk is selected — all revealed cards must go to the bottom.

### WHY this was missed
The `actFromActionWithId` path (player picks a Risk) correctly sinks the non-chosen cards via `createCardAddedToFactionDeckEvent(..., false)`. But the `actFromActionPass` path only sent a notification and fired `actionResolvedEvent` — no sink.

### How I found it
Direct comparison with `Action_01038` (Otto Streit), which has the **identical** reveal-pick-sink pattern but for Attachments instead of Risks. Otto's `actFromActionPass` correctly fetches the top cards and sinks them all. Gustavo's was missing that entire block.

### Fix
Added the sink loop to `actFromActionPass`: fetch top N cards (where N = Gustavo's ModifiedInfluence), queue `createCardAddedToFactionDeckEvent` with `false` (bottom) for each. Also updated the notification message to say "The cards have been sunk." matching Otto's pattern.

## Everything else checked out
- Negotiable: `$this->Negotiable = true` ✓ — `CityCharacter` base class exports it in `getPropertyArray`
- City Action prereqs (`isAvailableToPlayer`): parent check + controlled + in city ✓
- Reveal count: `$gustavo->ModifiedInfluence` ✓ (uses modified, not base)
- `handleEvent`: reveals top cards, announces Risks found, sets `MULTI_STATE_INITIATING_PLAYER`, calls `setUsed`/`resetPlayerPassCount`, queues transition ✓
- State flow: 01192 (multipleactiveplayer acknowledge) → 01192_2 (game: set current player) → 01192_3 (activeplayer: choose Risk) ✓
- `actFromActionWithId`: validates card is in top N, validates it's a Risk, removes from deck, adds to hand, sinks rest ✓
- Uses `stMultiPlayerInitSansInitiatingPlayer` (initiating player doesn't need to acknowledge their own reveal) — differs from 01038 which uses `stMultiPlayerInit`, but this is a reasonable UX choice, not a bug
